**Will Brown**

如果瓶颈是数据和真实专业能力，就像我们在节目开场讨论的那样：你更愿意请历史上最聪明的人，还是请一个在某个领域干了三十年的老手？很多时候经验积累更关键，因为深度理解一个问题往往不能被一条短提示替代。

真正的优势在于知识和最佳实践能否长期沉淀。机构和公司靠的是在既有基础上持续迭代，而不是每天从零开始。Prime Intellect 想把这种可复用的“累积能力”能力给更多公司。

随着软件和编程门槛下降，AI 研究里也出现了同样趋势：更多人能够上手。我们要把以前只在少数大实验室可用的基础设施开放出来，让更多团队真正获得同等起点。

**Dwarkesh Patel**

你们的任务是让更多人做 post-training。我想先确认一下，你们如何定义这个定位？

**Will Brown**

我们做的是一套从底层到上层的研究基础设施，尽量覆盖前沿训练所需全链路，从算力调度、训练框架、环境系统，到安全沙箱和评测。目标是给新创公司、企业和新实验室都提供可执行的入口。

我们强调的是开源科学与可落地商业价值：现在许多成功应用不是泛化文本 AI，而是针对某个任务做深度定制。要真正优化产品，就不能只做 prompt 级别调教，而要触达模型参数与结构优化。

**Dwarkesh Patel**

你们如何看待每家公司都要有自己模型栈的未来？

**Will Brown**

我们认为最终每家公司都会变成某种意义上的 AI 公司。大多数公司会保留自己的 AI 研究能力，无论是预训练、后训练还是面向专用流程的微调与蒸馏。尤其是很多任务并非纯文本生成，而是要为具体工作流持续迭代。

Prime Intellect 的 Lab 名称，就是想把“前沿研究实验室”做得像公共产品。我们强调 environment（环境）这个抽象：它不只服务强化学习，任何有可验证状态转移与任务反馈的系统都可以建模为 environment。

SWE-bench、AMIE、Terminal Bench 都是例子。环境里有任务集、交互方式和奖励函数。你平时离线评测的那类 eval，在我们看来也是一种环境，只是通常不用于训练。

我们平台让团队可以用同一套环境做后训练、评测、合成数据、强化学习优化。它像 GitHub 一样强调可复用、可协作、可共享，从而把“性能提升”变成可共享的工程过程。

以前大实验室拥有独占的优化闭环，像 ChatGPT、Claude Code 这样的产品就是在自家环境里反复迭代做起来的。现在更多创业公司也需要这种能力。

Cursor 是个重要案例：它把环境直接作为自己产品的一部分进行训练，形成闭环。我们认为这个方向会扩展，很多团队会先用 env 做现有产品优化，也会借此诞生新的产品形态。

**Dwarkesh Patel**

你前面说 environment 和 eval 有区别吗？能再讲清楚吗？

**Will Brown**

可以。eval 更像是问答式测试：你给一组问题、看模型答了什么。环境则更强调状态系统，模型在其中采取动作并改变状态，系统有明确目标和收益。也就是“有进展可测量”的闭环。

像 Atari 时代的 RL 强调长期交互，而大规模训练场景下也同样如此。关键是有明确目标函数，而不是靠人随手“看起来像这样就行”。

**Dwarkesh Patel**

那什么时候应该构建环境，什么时候应用直接把产品本身当成环境？

**Will Brown**

通常两种都要。比如 Rust 建模任务，你可能需要多套领域环境；如果产品本身是用户与 agent 交互界面，直接把它当环境也合理。核心在于你要能迭代并比较不同模型、提示和系统配置。

环境也是把应用优化器变成统一接口的方式。无论选择 Claude、GPT-5 还是 Gemini，你都需要用内部评测机制判断提示、端点与成本-性能的最佳组合。我们做的基础设施正是服务这一点。

**Dwarkesh Patel**

听起来 harness 也是关键。它和 RL 的关系是什么？

**Will Brown**

可以把 harness 看作环境中的一段关键接口。对于一项任务，输入、状态变化、输出与评分都在这条链里。环境负责定义任务世界，harness 负责模型如何同系统交互。不同 agent 场景下，harness 可以是 CLI、系统提示、工具调用甚至子 agent 编排。

所以我们用 environment 作为更通用的抽象，避免只盯着某一类 harness。模型交互的范式在不断扩展，我们要保持框架足够通用，不被单一定义卡住。

**Dwarkesh Patel**

那是不是每家公司都该用 environment 来后训练？

**Will Brown**

可以这么理解：环境不是“必须只做这件事”，而是“通用工具箱”。从大模型蒸馏到 prompt 优化、AB 测试、SFT，环境都能复用。你甚至可以把同一交互协议产出的数据再筛选回灌到微调。

这也解释了 eval 与 env 接近的原因：大家对某个场景性能的测量，本身就是一种 env 设计。区别是它可能不直接参与训练，但在工程上它们是同一套思维。

**Dwarkesh Patel**

那 post-training 是否等于 RL？

**Will Brown**

不完全等于。大规模场景下 RL 是最重的那一段，但还包括提示调优、SFT、蒸馏等。我们支持的是更完整的工具箱，让团队在不同阶段都能做可调优。

**Dwarkesh Patel**

Fortune 500 这类公司真的能上手吗？会不会太门槛高？

**Will Brown**

大公司通常有 AI 团队，能上手这套系统。真正的问题是门槛不在于“会不会用模型”，而是能否把训练链路做顺。你需要合适的工具把算力、代码执行、模型和评估打通。

而我们在客户侧投入更多，包含沙箱、终端隔离、快照等复杂工程。目标是降低调参和运行难度，让实验更像可复现的产品流程。

**Dwarkesh Patel**

你们有一些典型客户故事吗？

**Will Brown**

有。像 RCI 这样的 frontier 团队，他们既做 pre-training 也做 post-training。合作过程中他们的需求让我们把很多功能从 compute 编排一路补齐到推理部署。

还有一些更偏企业端的团队，像医疗 AI 场景：评测、调优、合规可信度都要求很高。平台帮助他们构建对外科、问答、检索等任务的专属环境，并持续改善可部署模型。

**Dwarkesh Patel**

你们看到人们会在教学阶段如何使用这些环境？

**Will Brown**

很多 grad 学生和新手开发者用它当训练“玩具场”。比如 Wordle 这类小型任务，是非常适合快速看到模型学习曲线的入门环境。

这类可控、可视化的小任务很重要，能在一两小时内在少量 GPU 上复现学习效果。很多人先从这些场景起步，再进阶到复杂环境。

我们的居住式项目组也在构建更复杂环境：软件工程验证、医疗物理、网络安全等，都在验证“可复现、可评价、可扩展”。平台会持续给这些方向补齐训练所需能力。

**Dwarkesh Patel**

网络安全环境听起来很重，能讲讲你们的做法吗？

**Will Brown**

我们有不少合作方在 CTF 一类场景里做实验：终端里有文件系统和工具，agent 在其中搜索、修改、执行命令。你可以在某个阶段判断任务是否完成，再由外部工具验证结果。

这类环境很适合发现隐藏 bug：模型有时会“钻空子”拿高分。通过不同任务、不同 rubrics，你能更早看见环境设计中的漏洞。

**Dwarkesh Patel**

这会不会有 sim-to-real 之争？真实复杂世界很难完全复现。

**Will Brown**

确实有，但重点是用什么级别的复杂度能解决你当前任务。很多场景不需要完整真实环境，而是要“足够对的近似”。像 web 搜索，你可决定要不要接入真实网络。

像数据库查询任务也是如此：如果任务只覆盖特定问题，没必要把全量数据都塞进环境。抽取必要子图，保留关键交互，能显著降低成本并加快训练。

所以平台的工作之一就是帮助定义“哪部分世界是核心”。让团队不用浪费算力在无关复杂度上，而是把计算投到关键环节。环境设计能力本身就是一项增长最快的核心。

我们也在持续扩展文档、skill 文件和工具链，避免团队把经验重复发明。研究团队越大，历史经验越容易被吸收进系统化资产，这一点对长期协作非常关键。

你问到是否“自然继承”了传统经验标注：我认为是。人类专家在很多任务上仍然比模型强，环境就是把专家的判断能力转移成可迭代监督。

核心在于抽取“什么是做对”的信息流。通过 yes/no 这类可判定问题、reward 模型、以及人类评估标准，RL 可以把高质量反馈转成训练信号。

**Dwarkesh Patel**

那为什么要建环境 hub？

**Will Brown**

因为单纯发到 GitHub 的环境太零散。Hub 的价值不只是共享环境定义，还包括统一评测流程、版本化、和在不同 trainer 之间快速接入。

我们已有自有的 Primer RL，也支持和其他 trainer 集成。这样团队就能在同一个生态里试验，而不用反复重建基础设施。

**Dwarkesh Patel**

社区里大家会共享吗？还是大多保留私有化？

**Will Brown**

两种都有。很多团队有商业机密不愿完全公开，但又愿意把通用部分放到社区。私有任务和公开基准并行，能同时兼顾竞争力与协作价值。

大家会把公开基准作为进度灯。除了验证自有任务，也用通用评测看是否存在泛化。Wiki Search 和 Wordle 是典型受欢迎模板。

从生态看，Wiki Search 很受欢迎，因为它是可复用模板：你只需替换文档即可在内部搜索场景中重用。大家喜欢这种“换材料不换框架”的效率。

**Dwarkesh Patel**

往未来看，你觉得 RL 的研究会往哪里走？

**Will Brown**

Andrej（Karpathy）说过 RL 很“像用吸管喝水”，效率低、信息密度不高。我部分同意：compute 需求高，但它有价值，因为高质量人类数据稀缺时，RL 允许用更多算力换更少数据。

当你没有金标准答案，或你已经用了最强 teacher 时，RL 的探索机制变得关键。计算前沿很大，这部分我们也在期待更多高效策略。

**Dwarkesh Patel**

你们怎么看开源模型和闭源模型在这个体系里的支持边界？

**Will Brown**

Trainer 这层通常需要权重才能做完整流程，但 environment 的方法论在开源和闭源都适用。我们可以在环境层统一做 eval、prompt tuning、模型选择、harness 评测。

对于闭源模型，常见做法是把环境和蒸馏流程结合起来，把目标输出通过平台方式沉淀再用于优化，而不一定必须拿到完整权重。

**Dwarkesh Patel**

那像 RL on closed model 的 agent harness 可以做吗？

**Will Brown**

可以。它与传统 RL 的边界逐渐模糊。现在有人在 prompt optimization、GEPA 这类方法中把优化搬到 prompt 空间，效果上和 RL 是平行方向。

在不同工具链里，优化系统提示、agent skill、工具调用策略，都是可以系统化迭代的。环境让这些参数都能被量化比较。

**Dwarkesh Patel**

最近 DSPY 推出的 Recursive Language Model 你怎么看？

**Will Brown**

非常有意思。我们一直在研究长期上下文如何由模型自身管理。核心不是一次性塞给模型全部上下文，而是让它在运行时维护和调用持久变量。

我们看到初步结果是，在长链路推理上确实有明显改善。给模型一个可管理自身上下文的工具，再配合子模块协作，会提高稳定性和效率。

未来几个月我们会把这类递归上下文框架真正训练起来，不只是喂给模型，而是让它学会主动使用这种机制。

**Dwarkesh Patel**

还有什么你最期待的研究方向？

**Will Brown**

合成数据是我很期待的方向。大家一直说持续学习，但真正落地还在起步。任务上讲，如何让模型自己构造更有价值的数据、甚至自己构建任务环境，是下一步很大的空间。

**Dwarkesh Patel**

如果都顺利，Prime Intellect 在未来世界里扮演什么角色？

**Will Brown**

我们希望 AI 的价值不被少数大厂垄断。尽可能让更多创业者和企业拥有自己的模型优化能力，像一个自己的“模型工程实验室”。

希望未来出现更多类似 Claude 之于文书、Cursor 之于开发的“普惠”时刻：企业能用自己的数据和流程反复优化，而不是被技术黑箱裹挟。

那套“每家公司都能做 AI lab”并不要求每个人都懂所有细节，但要有一条实用路径：让经验能持续复用、让评估可对齐、让优化可持续。

今天你听到了的核心就是：在数据和专长成为真正护城河的时代，组织要把 institutional knowledge 像软件一样版本化和复用，这也是我们推动环境与 Hub 的根本目标。
