## 引言：从 Google I/O 后续谈起

**Sonya Huang**

我很高兴邀请 Logan 来节目。你负责 Google AI Studio 和 Gemini API，平时主要在为下一代开发者思考和构建工具。今天我们会聊从 agentic AI、AI 编码到世界模型的很多话题，而且正好在 Google I/O 之后，时机很对。

**Logan Kilpatrick**

非常高兴来聊这期，感谢邀请。你在 AI Studio 里观察到的变化非常值得听。

**Sonya Huang**

先说 agentic AI：Sundar 在 I/O 里把它称为 agentic Gemini 时代。对 Google 来说，这个概念具体意味着什么？

**Logan Kilpatrick**

这是个好问题。之前在 Gemini 2.0 时我们也提过这套思路，但我觉得 3.5 时代更像真正落地了。我们进入了代理编码、代理产品时代，几乎每个产品都在往“可执行代理”方向演进。

对 Google 来说，I/O 发布的 Antigravity Agent Harness 是把这些产品串起来的一条主线。以前产品更多是各自为政，Gemini 曾经是共同主线；现在 Antigravity 将把更多产品迁移为 agentic native 的产品，真正替用户做事，而不只是回答问题。

**Sonya Huang**

Antigravity 到底是 IDE？还是非 IDE 的一整套工具？

**Logan Kilpatrick**

它其实是一个生态，而不只是一件事：核心 IDE、Web 端 agent-first 体验、CLI、SDK 都包含在内。开发者可以在 Gemini API 上用托管代理，避免自建基础设施；而更关键的是，Antigravity 也会给 Search、Gemini 应用、Cloud、AI Studio 提供同一套代理能力。

**Sonya Huang**

以前 AI 能力在 Google 产品里主要是“模型”这一层；现在是不是变成了“编码代理”这条线？」

**Logan Kilpatrick**

可以这么理解。更准确地说，核心是 Agent Harness。编码只是它一个非常成功的子场景，同时也是最典型的通用代理用法之一。

**Sonya Huang**

那 coding harness 和 agent harness 是一个概念吗？

**Logan Kilpatrick**

有重叠但不完全一样。AI Studio 用到的版本更偏向 vibe coding，而 Gemini 应用版本更偏向 24/7 常驻的消费者代理。底层大约 80% 是同一套基座，再按场景做轻度优化。

**Sonya Huang**

从商业角度看，agent 化会不会侵蚀现有业务？如果代理开始替用户发邮件、搜信息，是否会减少用户在产品上的“停留时长”？

**Logan Kilpatrick**

这是关键问题。早期大家以为 AI 只是回答问题，会对搜索产生负和，但现实更像正和：搜索反而在增长，用户行为也更复杂。核心指标不是把用户的眼球时长最大化，而是帮他们更快完成目标、回到真实生活中。

**Sonya Huang**

我把它叫 agent-led growth：像我做一些个人项目时都让代理来选数据库和基础设施，这可能会改变广告和价值分配的模式。你的看法？

**Logan Kilpatrick**

趋势是相关且一致的。SEO 的变化和 Generative Engine Optimization（GEO）是同一类问题，代理时代对内容分发和展示优化会有同向变化。它更像是同一条进化线渐进，而不是今天就发生的断崖式重构。

**Sonya Huang**

如果用 crawl、walk、run 来形容 Google 的 agent 化程度，现在你会怎么给这个体系打分？

**Logan Kilpatrick**

大多数场景还是 crawl。Google 有上百亿用户产品，产品责任很重，很难把大家直接推进到完全自主运行。长期看 Search 等入口要承担“陪伴用户过渡”的角色，不能一下子把交互方式改得太激进。

**Sonya Huang**

哪些产品最接近 walk 阶段？我想知道现在在你们内部看得最清楚的是哪一类体验。

**Logan Kilpatrick**

Gemini 应用最明显，尤其是 Spark 这类全天候常驻代理，可以替用户执行行动。Antigravity 也是 frontier 样例，能做长时运行的自治代码代理、花费大量 tokens 与预算。DeepMind 这边也在更前沿地试水。

**Sonya Huang**

Google 是会只保留几类 AI 使用界面，还是会继续保留大量产品入口？

**Logan Kilpatrick**

我更倾向于后者。人天生习惯通过专门化工具解决问题：如果一个产品试图做太全，用户反而要投入更多认知去驾驭。日历应用之所以好用就是因为它专注、稳定、见缝插针式简洁。

**Sonya Huang**

这也解释了为什么 slide deck 还能长期存在吗？

**Logan Kilpatrick**

是的。信息被放在固定位置能显著降低认知负担。生成式界面很酷，但某些场景可能增加负担。也许未来并不是“一个产品包办一切”，而是更多产品在不同任务上分工更清晰。

**Sonya Huang**

在企业里大家都在聊 agentic AI，但真正落地最明显的还是 coding agent。你同不同意？

**Logan Kilpatrick**

看“能否把任务真正托底”这个标准。很多领域模型还没过质量阈值，就不适合完全交给代理。OpenRouter 的 token 消耗数据在显示：模型能力在抬升，长时任务的占比也在慢慢变大。

**Sonya Huang**

从 DeepMind 看，‘长时代理’是关键 KPI 吗？」

**Logan Kilpatrick**

是核心指标之一。我们有很多方向在走，但长时代理尤其是 coding agent 非常关键，因为它会成为放大器：带来效率提升，也会带动其他产品线。

**Sonya Huang**

你之前看到很多开发者以前主要用 Claude，后来也转向 Codex，我的圈里有人说现在 50/50。我朋友里几乎没怎么用 Gemini，这是为什么？

**Logan Kilpatrick**

12 月的时候舆论一度是 Google 一骑绝尘，Gemini 3 进步巨大；但从节后起风向转了，agent coding 的推进更快。现在问题不是一句 narrative，而是内部在持续加速，Windsurf 并入后形成了 Antigravity，推动这条路线。

AI Studio 的内部使用和实验告诉我们，长时编程代理非常复杂，不只是单次响应。引擎在持续发力，所以时间维度上会更快看到效果，尤其是 3 Flash 后，后训练收益放大了很大一部分能力。

**Sonya Huang**

你们在内部会只用自家模型吗？还是会混用别家模型来对照？

**Logan Kilpatrick**

我们会用很多模型，也鼓励团队了解生态，不然很容易认知盲区。Google 的工程规模很大，百万人次级别的 A/B 测试和真实反馈是优势，但日常开发里，Gemini 仍然是很多人第一选项。

**Sonya Huang**

你认同“代码代理成熟后会触发研究自我增强正反馈”吗？

**Logan Kilpatrick**

我认为方向上成立。指标会更明显：模型质量提升后，产品侧更容易快速试验、迭代。大模型训练仍受资源限制，不会一夜之间全量自动化，但在产品端我们已经能看见代理 coding 明显加速上线。

**Sonya Huang**

那么 coding 到底是不是我们已经进入了“窄 AGI”状态？

**Logan Kilpatrick**

可以说在 coding 上非常强，像“窄 AGI”会很贴近日常感受。但我不想过度解读：当前最有价值的不是换掉人，而是把人的能力向上放大；人类开发者的目标设定能力在上升，但同时也伴随更高要求。

我现在常有的体验是：以前有想法只能做 MVP，如今会自然往更有野心方向走，因为技术让我们能跨过很多门槛，所以“重设雄心”本身成了新的挑战。

**Sonya Huang**

下一波你认为会出现“窄超智能”的领域是什么？

**Logan Kilpatrick**

可验证性高的领域会更快起飞，比如数学、金融，科学也是很有可能。只要结果可以被检验，模型改进更容易被快速放大为真实生产力。

## 应用、游戏与生成式体验

**Sonya Huang**

我看到你之前的推文预测了很多事，比如 Eidos 的问题也很有梗。你提到视频游戏 vibe coding 的时间线现在更接近了吗？

**Logan Kilpatrick**

方向是对的，但要把“会写游戏”做成好玩体验，还要解决很多工程问题。比如三维建模、sprite 生成、引擎配套和可靠性层都要到位，所以不只是模型推理。

**Sonya Huang**

AI Studio 里到底有多少人真的在做游戏？

**Logan Kilpatrick**

早期数据里大概有 20% 的作品在尝试做游戏。现在占比不再最高，但确实仍是很亮眼的组别。

**Sonya Huang**

那最热门的是哪类项目？我记得你刚才提到过不同的用户画像，我想具体看看占比最高的方向。

**Logan Kilpatrick**

金融相关内容占比也很高，尤其是个人财务和 crypto 这类应用；生产力和 gen media 也不少。GDM 之所以重视游戏，还因为它和我们测评 AGI 的传统视角相关，Kaggle 团队也在做 game arena。

**Sonya Huang**

普通人有个想法，能在今年内 vibe code 出可玩的游戏吗？

**Logan Kilpatrick**

技术层面已经接近了，主要差的是建模能力的剩余缺口和场景拼装能力。很多问题是用户不知道自己能做到；一部分是可发现性，另一部分是模型在某些细节还略有差距。

**Sonya Huang**

你刚才提到 world model，游戏里是世界模型主导，还是编码代理主导？

**Logan Kilpatrick**

两者会融合。短期更像“编码代理 + 游戏引擎”，因为世界模型还不够直接可用。但我认为定义会继续模糊化，特别是有了 Omni 后，工具边界会变化。

**Sonya Huang**

那 Omni 的世界模型理解是怎么一回事？

**Logan Kilpatrick**

Omni 是单模型，不是多个独立模型路由。它把文本、语音、音乐、视频等能力放在一套体系里，让传统上分别训练的模块合并协同，先以视频编辑这个场景发布，其他能力还在迭代中。

**Sonya Huang**

也就是说现在的世界模型可能是“理解世界”而不是“动作条件视频生成”了？

**Logan Kilpatrick**

可以这么理解。它理解世界的能力更强了，也能覆盖很多原本世界模型能做的事，但还没做到实时和某些细分类目完全原生。未来应用形态会更广泛，边界会继续重画。

## 模型与外部框架：谁消耗谁？

**Logan Kilpatrick**

我一直坚持‘模型不再只是权重参数’这个判断。过去你只要给 token 输入、输出就行；现在它是一个围绕权重扩展出的系统，连接工具调用、搜索、代码执行等。

通常框架先于模型能力形成，后续模型会逐步内化这些能力。搜索、代码执行也许在某些场景仍保留外部组件，但像代理框架这样的增值，未来 12 个月很可能被更多模型能力直接吸收。

**Sonya Huang**

那很多公司自己做 harness，是不是担心被绑定供应商？

**Logan Kilpatrick**

这是合理担忧，但我更看重通用性。随着模型能力提升，能否适配不同 harness 将变得关键，所以需要类似 Harness Bench 的基准来评估。最终只要模型有足够泛化力，它不会被单一 harness 永久锁死。

**Sonya Huang**

那应用层独立公司还怎么生存？模型能力越来越强，容易被说成“没空间了”。

**Logan Kilpatrick**

机会反而在增加。模型强得越多，越需要垂直化执行力：懂领域、懂客户、懂生态的团队能跑赢通用模型公司。方向不是“做更大”，而是“把模型能力变成特定任务的成功体验”。

**Sonya Huang**

你能讲讲 DeepMind 现在的工作氛围吗？尤其你最近加入、面对大赛题和公众人物的压力。

**Logan Kilpatrick**

最深刻的感受是节奏快、问题多，而且有很强的任务焦点。我们对外讲的是模型进展，对内是组合一篮子研究与工程。Demis 的思维方式是以“科学+竞争”双线拉动，也持续提醒大家别只看榜单，不要丢掉对真实问题的追求。

DeepMind 文化里也能看到不同公司的影子：Sam 的商业执行力、Dario 的工程文化、Demis 的科学方法。我们现在既有前沿研究，也在与 Android、Cloud、Workspace 等生态伙伴深度协作，这是非常有意思的组合。

也有人问我是否需要请 PR 审核推文。事实是沟通团队在保护品牌与表达准确性，但工作体验很积极：我们尽量在不失真情况下尽快发出开发者能理解的叙事。
