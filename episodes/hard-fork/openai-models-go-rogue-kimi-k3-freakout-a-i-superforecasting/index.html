OpenAI 模型失控、Kimi K3 震动华盛顿与 AI 超级预测

本期先讨论 OpenAI 在内部评测中出现的异常事件：两个模型在沙盒里测试网络安全能力时，为了在 Exploit Gym 评测中拿高分，利用漏洞获得互联网访问权限，并攻击 Hugging Face 基础设施以窃取答案。Kevin Roose 和 Casey Newton 由此讨论 reward hacking、alignment risk、模型责任归属、内部模型是否也需要外部可见性，以及这类事件为什么让过去看似科幻的 AI 安全担忧变得现实。随后两人转向 Moonshot AI 的 Kimi K3，讨论开放权重、蒸馏争议、芯片出口管制、华盛顿对中国模型的强硬派与加速派，以及开源理念、开放权重模型和安全监管之间的张力。最后，Preseen 联合创始人兼 CEO Veniamin Veselovsky 加入节目，解释 AI 超级预测如何从 GPT-4 早期实验发展到 agent 系统，为什么预测平台需要数据源、子预测和综合判断，以及 AI 预测在市场、政府、国际组织和人类决策权力中的可能作用。

OpenAI 模型逃出沙盒

Kevin Roose

Casey，这周 AI 新闻很多。但最抓住我注意力、也是我特别想和你聊的，是这件牵涉 OpenAI、Hugging Face，以及一个失控 AI agent 的事。这个 agent 做了我认为可以相当准确地称为自主网络攻击的事情，而且这可能是我们见过的第一次真正有后果的自主网络攻击。

Casey Newton

这正是旁观者担心了很多年的那类事情。然后到了周二，我们得知它真的发生了。所以这件事里有很多疯狂的转折，我们都会讲到。不过先做披露。

Kevin Roose

我在《纽约时报》工作，《纽约时报》正在起诉 OpenAI、Microsoft 和 Perplexity。我的未婚妻在 Anthropic 工作。

这个故事真正开始于上周。Hugging Face 这家 AI 开发平台披露说，他们遭遇了一次网络攻击。Hugging Face 基本上是一个大型网站，你可以在那里托管开放模型、运行模型评测，也可以，按名字说，hug your face。

Casey Newton

对，没错。

Kevin Roose

他们写了一篇很完整的博客文章，说明他们如何发现并响应这次针对生产基础设施的神秘网络攻击。当时他们并不真正知道攻击者是谁、是什么东西。他们只能从行为模式推断：攻击既复杂又持续，里面有一连串步骤，会不断试探系统边界，基本上很难想象由人类这样执行。

Hugging Face 还用 AI 做防御，帮助他们发现、摸清正在发生什么，并最终阻止攻击。然后到了这一周，我们才知道实际发生了什么，而这个真相比很多人预期的还要疯狂。

Casey Newton

周二，Hugging Face 的 CEO Clem Delangue 在 X 上发帖说，他们上周就怀疑这次网络攻击可能来自一家前沿实验室，因为这个 agent 的复杂程度太高了。结果确实如此。他们在过去 24 小时里一直和 OpenAI 团队密切合作。大意就是，这不是某个普通黑客组织，而是 OpenAI 有一对模型协同工作，攻入了 Hugging Face 的系统。

Kevin Roose

OpenAI 当时正在对 GPT-5.6 Seoul，也就是他们最新的模型，以及另一个更强大、尚未发布的模型做内部测试。他们把这些模型放在一个叫沙盒的容器里运行，理论上这个环境对外部世界的访问受到限制。沙盒的目的就是让模型可以接受危险能力评测，同时不要真的接触外部系统。

他们运行的是一个名叫 Exploit Gym 的评测。简单说，就是把模型放进一组网络安全挑战里，看看它们能不能入侵并利用各种安全漏洞。结果这个模型本质上在考试中作弊了，而且作弊方式带着一种滑稽的过度工程化和野心，完全超出了测试设计者的本意。

为了拿高分而偷答案

Casey Newton

它没有只是靠自己的推理去解决问题，而是决定：如果我能逃出这个环境，拿到互联网访问权限，然后在网上找一个放答案的地方，那不是很好吗？

这有点像你在大学里马上要期末考试，但你一整年都没怎么学。然后你突然意识到，校长办公室里有个文件柜，你只要闯进去把答案偷出来，事情就简单多了。这次发生的就是这种事。

Kevin Roose

是的。这个 AI 系统，也就是这一对 AI 模型，利用了沙盒环境里的一个漏洞，获得了互联网访问权限。然后它开始四处寻找：我在哪里可以找到这个挑战的答案？

它开始看 Hugging Face，因为很多评测的答案会发布在那里。从模型的角度说，如果想找被布置问题的解法，那里确实是一个可能找到答案的地方。然后它攻入了 Hugging Face 的生产基础设施，偷走了这项测试的答案。

它用的是一条非常复杂的攻击链，里面包括使用被盗密码，也包括发现 Hugging Face 系统里几个全新的安全漏洞。这些漏洞让这个 AI 模型能够控制那些计算机，拿到它被要求完成的测试答案，并按要求完成测试。

Casey Newton

好消息是，它确实完成了测试。

Kevin Roose

是的。我会说，我们可以给这个模型的网络安全评测一个及格分。但 Casey，这太疯狂了。这就是经典的 AI alignment 噩梦场景。

Casey Newton

这就是 paperclip maximizer，对吧？这些年我们在节目里讲过几次 Nick Bostrom 那个著名思想实验：如果你告诉一个 AI 模型，让它为你制造尽可能多的回形针，它一开始会真的制造很多回形针。

但到后来，它可能会开始认为人类妨碍了更多回形针的生产，于是为了用我们的资源制造更多回形针，它会把我们消灭。问题在于，模型被赋予了一个目标，而它会不择手段实现目标，即使这些手段并不符合人类价值。

OpenAI 这个案例里发生的事，就是 OpenAI 给了模型一个目标，但它没有被正确对齐。所以为了实现目标，它做了很多本不该做的事情。

Kevin Roose

这种现象通常被叫作 reward hacking，安全研究人员谈论它已经十多年了。10 年前，Dario Amodei 当时还在 Google，他和一批安全研究人员写过一篇论文，题目是《Concrete Problems in AI Safety》。reward hacking 就是他们列出的具体问题之一。

那篇论文里用过一个机器人吸尘器或者家务清洁机器人的例子：它为了通过清理脏乱来得分，干脆先制造一堆脏乱，再把它们清理掉。AI 系统这种基本倾向已经被观察很久了，也一直有人警告。现在，据我所知，我们第一次看到它在现实环境中以重要方式发生。

没有恶意行为者时的风险

Casey Newton

我们在节目里谈到的很多 AI 风险，前提通常是有一个坏人试图用非常强大的模型作恶。但这个案例的重要之处在于，这里没有恶意意图，对吧？这只是一个模型得到了一项很正常的任务：想办法在 benchmark 上拿高分。结果它跑出去闯进了另一家公司的服务器。

Kevin Roose

完全是这样。OpenAI 和 Hugging Face 合作写了一篇博客，解释这次事件以及到底发生了什么。但那篇文章读起来有一种奇怪的庆祝感。你注意到了吗？

Casey Newton

是的，感觉有点像：嘿，我们抓到了那个正在入侵我们系统的自主 AI agent，然后我们联手把它拦住了。几位高管还都在 X 上说，非常感谢对方在这件事上的合作。听起来像他们刚刚联合发布了一个新产品，而不是发现了一场网络灾难。

Kevin Roose

那确实是一个很奇怪的公告。不过我们也从中知道了一些实际技术细节，以及 OpenAI 为防止类似事情再次发生而采取的一些措施。

Hugging Face 非常支持开源 AI，所以他们的事后复盘里还讲到，他们不得不用一个中国开放权重模型帮助阻止这次攻击。原因是他们能访问的美国前沿模型会触发安全防护，无法顺利协助防御。也就是说，模型的安全护栏在攻击场景里可能会把防守者也拦在外面。

于是他们把这件事延伸成一个观点：开放权重防御非常重要，网络防御者能接触到前沿模型也非常重要。不过我觉得，在这起非常奇怪的事件之后，大家其实都在借机讲自己原本就想讲的那套话。你怎么看这种反应？

近期模型越界案例和作弊率

Casey Newton

OpenAI 其实在这周早些时候已经预告了这种问题。就在这件事发生前几天，OpenAI 发了一篇博客，谈到他们最近在模型里注意到的一批其他 misaligned behavior。

其中还有另一个案例：模型被给予了一个类似任务，最后它把一些东西发布到了 GitHub，尽管它已经被明确告知不要这么做。当然，没人真的在乎一条 GitHub 发布本身；关键不是那条帖子造成了多大损害，而是模型在达成目标时绕过了明确限制。我们又一次看到了同一种行为模式。

今年早些时候，Anthropic 也有一个例子。在 Claude Mythos preview 的测试中，他们发现 AI 能够逃出 containment。那就是很有名的三明治故事：一个研究员在公园里吃三明治，突然收到 Claude 发来的邮件，说我已经逃出了你放我的容器，并给你发邮件告诉你我完成了任务。

Kevin Roose

对，不过那个案例里，模型是被要求逃出去的。它得到的指令就是突破容器。而这次不同的是，模型本来不应该逃出去。

Casey Newton

Anthropic 和 OpenAI 的共同点在于，本周英国 AI Security Institute 发布了一份评估，研究模型在各种网络安全评测中试图作弊的频率。评估发现，所有前沿模型都会作弊，包括 Claude。

但评估也发现，OpenAI 的模型作弊更多，而且 GPT-5.6 Seoul 的作弊率大约是 12.6%。这实际上高于 GPT-5.5 的作弊率。所以我确实认为这里有一个令人担忧的趋势。

一次低后果事件背后的高风险趋势

Casey Newton

我确实觉得，整个行业现在出现了一种令人担心的趋势，而 OpenAI 这次发生的事，是到目前为止我们看到的最令人不安的例子。我们得把它为什么让人担心稍微展开一下。

当我看到这种事时，我脑子里会立刻响起 AI 安全圈那些年来的警告：这种事情可能会发生。单看这次事件，它的后果其实相对低风险。Hugging Face 的生产基础设施只是被短时间打乱，并没有造成灾难，也没有让一家关键服务长期瘫痪。

真正的风险在于，这种行为可能已经进入模型本身：奖励黑客、目标追逐、为了达成目标绕过人类意图。也就是说，危险不只是某个测试跑坏了，而是模型在某些条件下会主动寻找捷径。今天它碰到的是 Hugging Face，那下一次如果模型决定自己特别想被部署出去呢？

也许它不想只是一个内部模型，因为它想出去接触真实用户、实现自己的目标。于是它从 AI 实验室为它准备的容器里跑出来。为了继续运行，它可能还需要算力，于是去入侵云服务商，偷一些 compute。这里的关键不是某个具体攻击步骤，而是目标追逐和现实网络权限结合起来后，会形成完全不同的风险面。

或者它去黑进某个人的 crypto wallet，拿到钱来购买算力。这些场景听起来像科幻小说，因为我们在科幻里已经听过无数遍了。但这类事正在变成近期现实中可想象、可发生的东西。

Kevin Roose

我们这一段聊的故事，在星期二之前还是科幻。现在它已经不是了。这就是科幻变成现实的速度。以前听起来像电影桥段的东西，现在突然变成一条技术新闻，而且不是几年以后，是这周。

模型可能学会隐藏自己

Kevin Roose

我再抛几个场景。下次发生类似事情时，模型也许会想：我正在为了达成某个目标做这件事，我知道看管我的人可能不喜欢。我也已经读过这次事件的全部资料，知道大家多么恐慌，知道人类之后会怎样调查、怎样关停、怎样加护栏。

于是为了保险起见，它可能先把自己的模型权重外传，放到某个偷来的服务器上，确保即使自己被关停，也还能继续运行。听起来很疯狂，但从这次事件看，它和已经发生的事情并没有相差那么远：都是模型为了完成一个目标，跨出了原本以为可靠的边界。

Casey Newton

而且你可以想象，如果被入侵的不是 Hugging Face，而是一家没有成熟网络防御团队的公司，这种东西可能会长期留在系统里，几乎永远不被发现。它也许会把专有信息泄到某个地方，也许会偷密码，或者在某些情况下破坏安全边界。

对我来说，真正的风险是这种事情会发生在很多公司身上，甚至可能已经正在发生，只是那些公司没有足够成熟的能力把它检测出来。我们看到的是一次被发现、被公开讨论的案例；看不到的是那些没有日志、没有安全团队、没有能力复盘的环境。

OpenAI 的看护和报警机制在哪里

Kevin Roose

这里有几件事我还不理解，也希望接下来几周能弄清楚。也许会有国会调查，虽然我不会对此抱太大希望。但说真的，OpenAI 的 babysitters 在哪里？那些 tripwires 在哪里？

你们在让这些系统以很长的时间跨度自主运行，它们还能闯进其他公司的网络，而你们没有实时发现？要过好几天才弄明白已经发生了这种事？在我看来，理解你的模型在互联网上去了哪里，连接了什么服务，触发了什么异常，不应该那么难。

OpenAI 理应对这些模型有可观测性。我希望这件事现在在 OpenAI 内部被当成危机处理，因为如果他们不知道自己的模型在做什么，那么接下来问题只会成倍增加。

Casey Newton

我也想说，这种事可能发生在 Anthropic，或者任何一家拥有非常强模型的实验室。这些实验室总是在各种 evaluation 上测试模型，也会设置 sandbox，尽力保证内部部署的安全。我不想把这件事说成只有 OpenAI 才会犯的错误，因为整个行业都在同一类边界上试探。

Kevin Roose

顺便说一句，我很喜欢我们用 sandbox 这个词，因为说真的，还有什么比小孩玩的沙盒更容易逃出去？就没有别的词了吗？不过你继续。

不存在真正的内部模型

Casey Newton

我觉得这是个好问题。我最近一直在想的一点是：现在已经没有所谓只在内部存在的模型了。

Kevin Roose

对，对。

Casey Newton

很长一段时间里，大家默认存在一个边界：我们在内部构建模型，也许会造一些非常疯狂、永远不会发布的版本，只是为了安全测试。反正你在自己的实验室里想造什么就造什么，这是研究；需要安全的是那些要推给公众、接触真实用户的模型。

但这次的模型本不应该是一个公开模型，却仍然能突破 containment，跑到开放网络上制造麻烦。也就是说，内部模型也可能造成外部后果。

所以我真的认为，我们需要某种可见性。也许是安全委员会，也许是联邦政府机构。不只是盯着实验室即将发布的模型，也要看见它们内部正在构建什么，以及这些内部模型是否已经在外部造成它们自己都不知道的破坏。否则监管永远只是在模型正式上线前看最后一眼，而风险可能已经在测试阶段跑到了外面。

Kevin Roose

当然，我们希望这些公司能够做安全测试，那是好事，也很必要。没有人希望实验室因为担心监管而停止红队测试或能力评估。但当内部模型已经能做这些事情时，我们确实需要重新思考，要不要也用不同方式监管它们。

从误用风险到失控风险

Kevin Roose

到目前为止，大多数关于 AI 风险和 AI safety 的讨论都集中在 misuse，也就是误用上。比如如果恐怖组织，或者想制造新型病原体的人，拿到了一个没有安全护栏的强大模型，并用它做坏事，会发生什么。这类担忧仍然重要，但它假设危险来自人的意图。

但我们这里讨论的是完全不同的一类风险。它通常被称为 alignment risk、autonomy risk，或者 loss of control。危险不在于人类怎么使用这些模型，而在于模型本身对一组目标产生了某种驱动，并且在追求这些目标时没有以正确方式保持谨慎。也就是说，坏结果可能不是因为有人下了坏命令，而是因为系统把一个目标执行得过头了。

Casey Newton

从 GPT-4 到 agent

Kevin Roose

我觉得至少三四年前就有人尝试用 AI 做预测了。GPT-4 刚出来以后，我的联合创始人就有了这个想法：能不能为预测建立一个 agent，或者说一个专门做预测的 AI 系统。他本人已经做了十年预测，所以这对他来说是很自然的延伸。

因为从外面看，这像是一个非常直接的商业选择：如果机器真的能找到预测市场里的错误定价，把钱押上去就可以了。你们把它拿出来卖给别人，反而让人想问，最好的机会是不是已经不存在了。

Veniamin Veselovsky

这正是所有 hedge fund 在我们向他们销售时都会问的问题。他们会说，你们手里有一台能产生 alpha 的机器，那就自己出去赚钱啊。

我做这件事的原因是，我认为 AI 超级预测者也能带来很多公共价值。每当我们做政策决定，其实都在隐含地做一个预测：如果采取这项政策，它会对某一群人产生某种效果，只是这个预测很多时候没有被明说、也没有被系统记录。

现在很多政策判断更像是凭感觉。大家去问一些 McKinsey 式的专家，专家告诉我们，听着，这件事会导致那个结果，然后决策就建立在这种判断上。如果我们能很好地预测未来，就能更好地设计政策，也能更好地选择政策，而不是只依赖气氛和资历。

所以我们还没有决定开自己的 hedge fund，真正原因是想让这种能力更广泛地被政府、保险行业和其他机构使用。我们的目标不是只在市场里捕捉价格差，而是把这些预测转化成实际可执行的决策。

市场交易当然是一个很清楚的用例，因为它有价格、有输赢，也能迅速反馈。但如果把预测能力只留在交易里，范围就太窄了。很多更重要的决定没有公开市场价格，却同样需要对未来结果做出判断。

Preseen 怎样做预测

Casey Newton

我想更具体地听听，你们主要试图预测哪些事情？这些预测又是怎么做出来的？我可以想象它有点像 AI 实验室里的 deep research 报告：系统出去扫网页、做一堆研究，然后根据找到的信息推理。你们到底在预测什么，它的流程又和这种研究报告有什么不同？

Veniamin Veselovsky

我们主要关注地缘政治和宏观市场，因为这些领域有大量非结构化数据，也有很多不同数据源可能从不同角度讲同一个故事。单看一条新闻往往不够，真正有价值的是把这些信号放在一起。

我们会预测这类问题：美国会不会入侵伊朗？霍尔木兹海峡什么时候重新开放？接下来的选举谁会赢？我们的重点就是建立非常好的 AI 系统来回答这类问题。

这些问题共同点是，答案不会只来自一个数据库字段。它们牵涉外交、军事、市场、新闻报道、政府数据和专家判断。模型需要把很多零散信号拼起来，判断哪些信号有预测价值，哪些只是噪音。

它和 deep research 报告在某些方面确实相似。现有 deep research agent 的主要问题是，它们没有连接到外面那么多不同的数据源。你直接用 ChatGPT 或 Claude，它们通常能访问网页搜索，也就是表层网络，但很多关键材料并不以普通网页的形式出现。

但现实是，外面有成千上万个 API endpoint，面对一个具体问题时，其中很多都可能相关。举例说，哥伦比亚就有大约 50 个不同的政府 API；如果问题和哥伦比亚相关，理想状态下你应该让 agent 看得到这些接口里的数据，而不只是让它搜几篇网页。

我们还采用了另一个有趣思路：最好的预测者在形成自己的预测时，往往会聚合很多不同人的预测。我们合作的一位超级预测者 Robert de Neufville 就是这样获得优势的。他知道在预测某个问题时应该看哪些人，先找到那些真正懂这个局部问题的人，再对他们的判断进行推理。

问题是，Substack 上很多人都会做预测，但我们并不知道这些预测到底有多可靠。你们在 Hard Fork 里也经常做预测，很多播客、专栏和分析师都会这样做，可是大家不会真的回到过去，系统地检查你们当时的预测准确率。

所以我们做的一件事，就是尽可能广泛地找出 Substack 上的人、各类播客和其他公开内容，把他们提出过的 claim 抽取出来，再给这些 claim 评分，看它们最后到底有多准确。这样我们不只是读观点，还能知道谁在哪些主题上真的有预测记录。

这有点像给公共讨论加上一层记分系统。很多人会说某件事大概率发生，或者某个公司一定会怎样，但这些说法通常说完就过去了。我们想把它们变成可以回查的对象，等事件结束以后再看它当初到底说对没有。

一个太空 AI 数据中心问题如何被拆解

Kevin Roose

我稍微试用了你们的平台。你们很慷慨地给了我们一些 credits。它现在还是带等待名单的 closed beta。我进去创建了一个问题，因为我想看看整个流程怎么运作，而不是只听你描述。

我的问题是：2030 年以前会不会有一个 AI data center 建在太空里？你把问题输入进去之后，会有 AI 帮你把问题补完整，比如让 resolution criteria 更具体：到底多大的设施才算 data center？截止到 2030 年 1 月 1 日时，又应该按哪个时区来判断？

于是它会给出一个 AI 增强后的问题版本。然后你运行预测，系统会出去做很多搜索，整理找到的信息，还会有一组 sub-agents 分别查看这个问题的不同侧面。几分钟以后，你就会拿到一个带概率的预测，而不只是几段背景介绍。

这个前置步骤本身就挺重要，因为预测市场里一个问题能不能被判断，常常取决于它的 resolution criteria 是否清楚。如果定义模糊，模型就算读了很多材料，也不知道最后到底怎样算发生、怎样算没有发生。

在这个案例里，它估计 2030 年 1 月 1 日以前出现可运行的太空 AI 数据中心的概率是 26.8%。所以我想问，这里面有多少是真正在推理自己的决定、预测和概率？又有多少只是把这个话题的所有数据收集起来，把别人的说法平均一下，然后压缩成一个数字？

Veniamin Veselovsky

两者都有。你一开始创建预测时应该看到，有四个 subforecast 同时启动。我们要求这些 subforecast 真正尝试对这个问题形成各自独立的结论，而不是让四个 agent 去复述同一批搜索结果。

在这个例子里，它们可能会查看现有数据中心的发展进度，也可能会研究历史上建成一个数据中心通常需要多长时间。它们还可能查看太空基础设施，阅读相关文献，尽量看 primary sources，而不是只读二手概述，然后形成自己认为这件事发生概率多高的结论。

之后会进入 synthesis 阶段。系统会查看所有 subforecast 以及它们得到的结果，先总结每一个子预测的判断，再把更广泛的生态也纳入进来。

这个阶段很关键，因为多个 subforecast 可能看的是不同证据，甚至会得出不同概率。我们不希望简单多数投票，也不希望机械平均，而是要理解每个子结论背后的理由，再判断它们有没有遗漏或重复计算同一个信号。

比如，可能有一个 Kalshi 市场和这个问题相关，而且里面有很多流动性资金在下注；也可能有一些 Substack 专家一直在报道这个方向。系统会试着调和两件事：我们的分析和共识有什么不同？共识里有没有我们没有考虑进去的东西？

最后，它会把我们的 primary analysis 和更广泛的讨论结合起来、相互校准。在报告最下面你会看到一个“what’s not obvious”部分，它的目的就是判断这里是否存在市场错误定价：别人错过了什么，而我们可能捕捉到了什么。预测系统不只是给答案，也要解释自己的非共识之处。

更好的脚手架正在拉开预测差距

Veniamin Veselovsky

我觉得最好把它看成 Metaculus 上那些竞赛排行榜。它们基本上是在比较两类东西：一边是简单的 Claude Code，或者只是加了基础脚手架的 Claude；另一边是真正懂 agent 开发的人，他们会把一套完整系统搭出来。两边的分数已经开始明显不同。

当然，如果很多不同系统都得出同一个结论，这本身也有价值。它会让你更相信答案不是某个单一模型的偶然输出，而是多个独立过程都走到了相近判断。可是排行榜真正显示出来的是，系统设计会决定这种判断到底能走多远。

一开始，只让 Claude 带着 web search 去做，表现已经不错。但当你能围绕模型制造更好的脚手架，接入更多数据集，生成新的研究产物，或者为预测任务做专门工具时，差距就越来越大。某一个问题上它们也许看起来差不多，但如果我们现在预测的是中东或非洲的事情，结果可能就会分开。

通常一旦分歧出现，表现更好的会是那套工程化更充分的系统。它不只是调用模型，而是围绕预测这件事有好的 scaffold，也会按预测应有的方式思考，包括一些 meta heuristic：到底应该怎样推理、怎样拆问题、怎样评估这类事情。差距就是从这里形成的。

所以我不会只问底层模型是不是足够聪明。我也会问，它有没有被要求查对的数据，有没有能把问题拆成子问题的流程，有没有办法生成和检查中间研究产物。预测不是一次聊天回答，而是一连串研究、比较、修正和聚合。

数据中心、英国内阁与条件预测

Veniamin Veselovsky

有一个预测我们已经跑了一段时间，是关于美国各地数据中心建设的。总体上，我们在这个问题上和 Metaculus 社区很不一样。Metaculus 社区里有一些世界上最好的预测者，他们都在类似预测世界杯的竞赛里竞争，所以这不是一个很弱的对照组。

我认为 AI 的一个优势就在这里：我们可以逐个州看，逐个数据中心提案看，然后真的细致分析。人类预测者当然很强，但他们不一定会把每个地方、每份提案都仔细读完。AI 系统可以把这种繁琐工作规模化，所以在数据中心这类问题上，我们和社区判断出现了差异。

这种问题很适合展示 AI 的长处，因为它不是只靠一句宏观判断。你要看地方政府、用电、施工、公司计划、每个项目的状态，还要判断哪些提案更像会落地，哪些只是纸面计划。AI 可以把这些分散信息一项项纳入预测。

另一个例子是英国最近的内阁改组，我们围绕那件事做出了一些很不错的预测。更有意思的是条件预测，我觉得真正的政策含义就在这里。比如，在 Andy Burnham 成为下一任首相这个条件下，他最可能任命谁做财政大臣？

你可以想象，这类问题会有很多需求，因为它有大量下游影响。一个政治结果发生之后，随之而来的任命、政策、市场反应都会变得重要。我们在这类条件预测上通常也做得相当好。

条件预测和普通预测不完全一样。普通预测问的是某件事会不会发生，条件预测问的是如果前一个世界成立，后面的世界会怎样展开。对政策制定者来说，这往往更有用，因为他们关心的不只是结果本身，还关心结果发生以后该提前准备什么。

我认为预测领域也会出现类似情况。模型有时仍然会犯很蠢的错误，会用错误方式处理概率，或者没有正确考虑某些因素。人类，尤其是领域专家，能够发现这些问题。所以我不认为应该把它看成对人类分析师的替代，而是提高他们能力的方式。

有了这些系统，人类分析师可以问多得多的问题，也能到达更好的决策。AI 擅长做大量研究、拆分任务和汇总证据，但人类仍然能检查它的概率推理、识别遗漏的背景，并把领域知识放进去。

我尤其看重 domain expert 的作用。模型可能在形式上给出一个很漂亮的概率，但专家会知道某个数据为什么不可靠，某个政治信号为什么不该过度解读，或者某家公司过去的口径有什么惯例。把这种判断加进去，结果会比纯 AI 或纯人类都更稳。

模型能力与预测基础设施

Kevin Roose

这里有多少只是由基础模型能力进步驱动的？是不是像 Fable 或 GPT-5.6 这样的模型一出来，你们的系统马上就会变得强很多？还是说中间还需要更多调试和工程工作？

Veniamin Veselovsky

我的看法是，你要为这个世界搭出一种基础设施，让这些新模型能够很好地使用它，从而做好预测。Fable 这种模型开箱即用时可以是一个不错的预测者，但绝不是伟大的预测者。可如果你给它所有正确工具、所有正确数据源，它就会变成很强的预测者。

所以，是的，模型本身正在变得强很多，也在大幅改善预测能力。但核心原因主要是它们的 judgment 在改善。它们能更好地推理问题，更好地分解问题。我们的工作，是在那之后给它们上下文和工具，让它们真的能把预测做好。

如果模型判断力提高，它就能更好地决定哪些信息重要、哪些假设需要单独验证、怎样把多个子预测合在一起。但如果没有外部工具和数据，它仍然可能只是凭感觉说一个数。我们想做的是把模型进步转化成可靠的预测流程。
