记忆与持续学习：Engram 的 Dan Biderman 与 Jessy Lin

本期节目邀请 Engram 联合创始人 Dan Biderman 和 Jessy Lin，讨论持续学习为何是 AI 的下一阶段基础能力。节目围绕一个核心命题展开：模型是否只能依赖外部检索与上下文窗口，还是应把公司与团队长期工作语境持续烙入权重。嘉宾认为只有把记忆、检索、系统工程和训练信号打通，才能在企业真实场景里降低 token 消耗并提高适配性。对话同时覆盖了“该内化还是外置”的边界、RAG 与权重更新的关系、缓存成本、以及未来个人化模型如何在隐私与效率之间取舍。

开场

Jessy Lin

预训练或后训练为什么能让模型在很多情况下“神奇”地泛化，以及如何把这个过程受控地用于企业私有数据的学习？关键是能不能让模型像会背诵常识一样，学会企业专属知识。这个问题非常有意思。

Sonya Huang

欢迎来到 Training Data。很高兴今天请到 Engram 的联合创始人 Dan Biderman 和 Jessy Lin。Engram 是一个专注于记忆与持续学习的 NeoLab。我们今天也很期待和你们深入讨论这两个当下 AI 研究里最热门的话题。

Dan Biderman

太好了，能来很开心。

模型始终在学习是什么意思

Sonya Huang

先开场提问：Engram 的网站说‘我们不再用单纯预训练和后训练的视角看问题，我们的模型始终在学习。’这句话怎么理解？

Jessy Lin

我认为现在模型确实已经懂了很多知识，但真正限制它更有用的，不是生硬的智能水平，而是对新情境和新任务的理解。你在做一个新任务时，怎样像在预训练/后训练中那样，把上下文深度烙印进权重？这就是我们关注的记忆和持续学习两件事，也就是如何让模型学会新知识并真正内化到参数里。

Sonya Huang

那你们是否认为把上下文塞进窗口里、当作单独数据库的那种做法，其实不算真正的记忆和持续学习？

Jessy Lin

我觉得这些方法会共存。现在很多人会用上下文工程：写超长提示词、多轮长对话，反复重组上下文来帮助模型理解目标。工具、上下文工程确实有作用，但更值得强调的是：我们可以把前沿模型团队的同一套训练流程和工作流，应用到公司里的各种领域和上下文中，而不是只停留在公开语料上。

Dan Biderman

我个人觉得这像做笔记和便签：再宝贵也不能丢。第二天回到工作后，我们仍然保留着脑中的记忆痕迹与直觉，知道往哪里找。当前很多方案本质还是外部化记忆。

但这有两个问题：第一，团队和个人每天会产生成千上万甚至更多文本。保存、检索、反复读取都很贵；更麻烦的是，没有更强的方法，模型很难在这些庞大上下文中理清重点。

Sonya Huang

你听起来是说，可能是几十亿甚至更多 token 的量级。

Dan Biderman

对，差不多如此。

Shaun Maguire

看你当天的情况而定。

Sonya Huang

能否讲讲 Engram 的架构和产品是怎么工作的？

Jessy Lin

我先说高层逻辑。我们希望让模型理解任何工作空间里的上下文。以 Notion、Microsoft、Harvey 等长期协作场景为例，里面有大量文档、对话和交互反馈，都是企业知识的一部分。模型不能只在测试时读文件，而要像在公司长期工作的员工一样理解全局。

我们是在工作空间内对团队模型持续训练，让它们理解上下文并随时间提升。技术上主要是把知识烙入权重：大量 adapter 微调（LoRA、前缀、稀疏结构等）都有；关键是把原始文档和交互数据转成高质量训练信号。我们会结合监督微调、RL、on-policy 蒸馏等方法，把这些模块融合起来做持续学习。

Dan Biderman

这并不是否定工具。我们假设模型始终有一部分知识是外部化的，也有工具可用。难点是判断什么应该进权重，什么可以外置。很多企业的专属流程和工具链很不一样，不是每家公司都使用相同的 Bash 或标准命令，因此让模型理解你的‘专属系统’非常关键。

Sonya Huang

也就是说，我在 Notion 里接一个代理，是否是做成 LoRA 调优后的定制代理，它会持续学习我工作区新加的内容？

Dan Biderman

没错。我们会和很多模型合作，服务多家一线 Frontier 模型团队，而且他们可能会持续采用这类方案。

Sonya Huang

这种方法能用在闭源 frontier 模型吗？

Dan Biderman

需要白盒访问权重，我们可以和闭源厂商合作，但最容易落地的是开源模型。只要是 transformer 架构，本质都可以接入同样的思路。

Sonya Huang

那对比前后效果时，交易线是什么？是不是前期投入更多算力训练企业知识，推理时就可以少发很多上下文？

Dan Biderman

是的。你不再反复检索、反复重读、反复写复杂的 system prompt，推理 token 消耗可以降两个数量级。很多关于人员、团队、组织优先级的内容，不会在单一文档里完整记载，模型从数据中内化后，可能在 100 个 token 内回答，而 baseline frontier 模型可能要 100,000 个 token 才能完成。

另外，还有质量层面。当前代模型在一些场景仍有 3 到 6 个月的滞后，人造任务常常是特定且专业。即使这些任务未来会被通用模型覆盖，先提前自学习，仍能在中期快速带来能力收益。

Sonya Huang

你们为什么偏向团队级别训练，而不是个人级别？

Dan Biderman

两者都可以。先从团队切入更容易，因为团队上下文更稳定，沉淀更丰富；但个人终端也会是目标。未来每个人的电脑和手机都可能接入。现阶段我认为知识协作团队里信息密度更高。

Sonya Huang

现在大模型内置了很多事实记忆，这算是优点还是缺点？有观点认为模型背答案（如法国首都是巴黎）会带来问题，宁可学会‘国家和首都’这种概念而不是死记硬背，你怎么看？

Jessy Lin

这是个关键问题。一定程度上，复杂推理需要一些事实作为材料。真正缺失的是：什么该记、什么可不记。许多学术基准只测很具体的事实，比如某个非洲国家某座桥的长度，这类信息不一定值得模型长期占用容量。

所以即使是人类记忆也很有损耗：要筛掉不重要的内容、保留可迁移的结构。事实学习和非事实学习、技能学习其实难以完全切开。你让模型剥离全部事实，很多基础能力会塌掉。

Sonya Huang

为什么需要这些事实？不能都靠查？

Jessy Lin

在推理链条里，很多步骤都需要先验事实支撑。你如果每次都先去查，再做下一步，效率和表现都受限。持续学习的价值就在于把关键知识内化，让模型更深入地展开复杂思考。

Dan Biderman

过去也有人尝试分离检索和内化，但代价很大。传统上数据库负责事实，算法负责处理信息；现在深度学习把它们融合了。我们需要更多可解释性研究来拆解这套机制。企业里也会出现这种趋势：泛化模型对所有场景陌生，行业里则用自己的上下文细化。

Sonya Huang

换句话说，算法和数据库并非天生两条线，核心是判断‘重要且可留存的内容’。

Jessy Lin

没错。

类比与实验动机

Sonya Huang

你们在谈到‘梦’这个比喻。在排序和持续学习上有受它启发吗？

Jessy Lin

有一点松散的借鉴。缺失的是一个‘消化并内化’阶段：现在多数都在测试时思考，但如果把这一轮经验回灌模型，下次就能更快、犯更少错、推进更顺畅。

Dan Biderman

‘像梦一样的AI’听上去有点怪，但有意思。梦里我们实验行为边界、社交场景和能力边界。对我们来说，就是给模型‘回去休整’的时间，在环境里探索自己的可行性边界，测试极端尾部问题。

Shaun Maguire

你们都偏学术背景，能给一个典型成功案例吗？

Dan Biderman

给一个假设：比如 OpenAI 要在一周后赢得一场数学竞赛，会不会先把数学教材都人工整理索引，还是先快速构建训练数据、跑训练再评估迭代？显然后者效率更高。这种‘训练魔力’不应只在少数高风险领域里掌握，应该放到更多人和场景。

Shaun Maguire

为什么不是由 frontier 模型厂商把这个端到端产品做出来？你们要怎么在巨头之间取舍？

Jessy Lin

我们和 frontier 的世界观有差异：不是只往更大更通用模型赌，反而是每个人都该有自己的模型。很多知识是私有的、冲突的、甚至彼此对立的。通用训练方式在‘干净监督+奖励信号’下很难学习到真实世界中的歧义任务。

Dan Biderman

frontier 团队追求的是 AGI、通用能力、再自动化经济，这条路径需要更大模型、更多数据和更长计算。我们同样重视记忆和持续学习，但认为它需要专门做成产品化能力并独立突破。Demis 在 Sequoia 讨论会上已经明确提到这个方向。

另一个关键是激励与所有权：如果我们能在不要求每家每次都‘挨个并肩共学’的前提下，从大量人和组织上学习，那是很大的解锁。

Jessy Lin

我认为世界会改很多。除了研究突破，还需要更小模型训练基础设施，不能只靠一次大规模训练。更重要的，是研究和产品闭环：现在 frontier 常见是研究训练后再交给产品团队搭壳，而在‘持续训练’世界里，用户输入和训练信号是紧耦合的。

Sonya Huang

是什么推动你们做这件事？

Jessy Lin

这是 AI 里的大问题。模型已经很智能，接下来剩下的是：它缺的是如何把‘剩余价值’学会。当前预训练像是世界给模型丢了海量多样数据，偶然形成了很多能力；现在要解决的是：怎么让公司、团队、个人自己的上下文也达到同级别价值。

Sonya Huang

Dan 你有神经科学背景，这也是你转做这块的原因吗？

Dan Biderman

是的。我最初研究意识和人类认知。后来意识到记忆和持续学习在 AI 里同样是核心，也发现现有系统与人类记忆机制差得很远。

Sonya Huang

你认为模型有意识吗？

Dan Biderman

我没有确定答案，但我不这么认为。更有意思的是理解人类如何感知和推理。Amos Tversky 提过，他更关注人的自然‘缺点’。我同样研究的是：人类在高效表征和抽象连接方面有天然优势，而现代系统很多时候还差很远。

硬件与架构讨论

Shaun Maguire

你们从学术界来，关于模型是怎么通过训练形成能力，前面有没有一个直观模型？现在是不是所有模型都在收敛成一个‘GPU 处理器’？还是会分化出类似人类大脑的记忆模块？

Sonya Huang

也就是说记忆是 emergent 的，还是会有专门记忆模块？

Shaun Maguire

几乎可以这么说，智能里很多能力是不是都能靠更大规模训练和更大数据自动冒出来？

Dan Biderman

从部署上看，不止 GPU，还出现了很多沙盒化能力。前沿实验也显示，只要规模化训练，很多东西会增强，但并不意味着单一通道就够。

Shaun Maguire

我指的是模型架构层面，不是部署层面。

Dan Biderman

在传统 state-space 等架构上也尝试了很久，目标是处理更长上下文。代价通常是记忆和精度权衡，在“计算量视角的记忆”上也如此。你可以把更多算力投入未见上下文，这是更关键的问题。

Shaun Maguire

有些模型声称它们是次二次方复杂度。

Dan Biderman

有的确实做到了，但我们在实践里看到精度一般会受损。并没有免费的午餐。若想理解像 Shaun 这种用户数据和工作习惯，反复读文件并不能替代：模型必须从这些信号中持续吸收。

Shaun Maguire

‘special’这个词有点挖苦。

Dan Biderman

哈哈，得给这种人训练 100 万亿参数级别才能覆盖。

Sonya Huang

大家更关心模型学习的价值到底是什么？是记住组织事实，还是把流程和工作方式内化，比如某些任务的操作风格？这也决定你们如何排列记忆槽优先级。

Jessy Lin

重点通常是让模型在你自己的 use case 上工作得更好。你可能想让它按品牌风格设计网站，也可能想让它按个人习惯写作、跑工作流。事实和技能并不绝对分离，方法在当前阶段是通用的。

Dan Biderman

对很多应用层来说，模型本质是前沿模型+搜索工具的循环。企业希望更快更准、更上下文相关地调用自己的数据。我们希望形成一种更高效的方式：把公司内部常识和人物分工内化进去，让模型不必每次都检索。

Sonya Huang

你刚才说这像‘RAG killer’，我想再确认：是要在权重更新和 RAG 检索之间做权衡？还是都要做？哪些内容进权重，哪些外置？

Dan Biderman

这是未解之题，行业还没有统一答案。它本质类似生物记忆问题：哪些该长期留在模型里，哪些放在外部？今年我住处的酒店房间号一年后就不必记住；但家庭密码可能要内化更久。

因此我们刻意减少启发式规则。人类并不是只看垃圾过滤后学习；在噪声环境里依然能形成稳定认知。模型也需要类似鲁棒性，而不是只做‘保留/丢弃’的粗过滤。

Jessy Lin

短期内，大量用户更担心的是日常运行 agent 的推理成本。

Sonya Huang

高推理成本有时候也未必是坏事。

Jessy Lin

我们得先问‘为何消耗这些 token’。Sonya 在 Fireworks 也常研究这块，大家都很关注。

Shaun Maguire

Sonya 的确很喜欢推理。

Sonya Huang

我也很喜欢推理。

Dan Biderman

我们也喜欢。短期痛点就在于重复读取。

Jessy Lin

在同一家公司、同一批文档上反复问同一问题非常常见。模型应该从历史中知道该知道什么，而不是每次都重新查。

Sonya Huang

缓存不能解决吗？

Jessy Lin

有一定帮助，但不能替代‘内化与泛化’。如果你总是 RAG 检索，模型难以产生“你还没问到但我应该提醒你”的联想。内化权重才更容易形成这种跳跃。

Dan Biderman

检索系统的核心问题不只是存什么、放哪里，而是如何查、该查什么。模型常常连查询目标都不清楚。

Jessy Lin

是的，知识分配本身是隐含的启发式过程。即使有检索，也不是只会‘你说我要查这个，我就查这个’。

Dan Biderman

而且我们对缓存成本非常敏感。KV cache 本质很重：一篇维基条目就可能占十几到八十 GB HBM。对比模型参数百 GB 级别，这种冗余很惊人。

我们设想的方向是，先离线用算力把这块表示压缩掉，降到原来的 1/1000，不仅推理更快，表示保真度也可能更可控。

Sonya Huang

非常有意思。

Shaun Maguire

在未来一年到两年，什么事件会像 ChatGPT 一样，让大家真正看到 memory 的‘时刻’？或者这个方向不会那样爆发？

Jessy Lin

大家都在等一个证明：持续学习下，模型像实习生一样越教越好。当前的上下文工程还没完全拿到这个结果。我们相信，需要多种训练工具协同，才能出现‘它确实在进步’的体验。

Dan Biderman

对，ChatGPT 的出现本身也不是预先预期好的。大多数产品路线在那之前就已经写好了。现在问题是：如果你单独用 OpenAI、Anthropic 一天到晚调 context，个人能提升的幅度非常有限。真正想突破的人得在自己的数据上持续训练。

核心难点是扩大算力，把数据训练进系统且不破坏模型稳定性。做到这一点才会让‘投入时间’真正转化成性能质量，而不是只是花更多精力。

实践经验与未来五到十年

Shaun Maguire

随便聊一会儿：你们最近什么 AI 变化让你最惊讶？

Dan Biderman

说到筹款新闻。我每天都能被惊到。Coding agent 的能力近期也有显著变化，大家都有感知。

Sonya Huang

哈哈。

Dan Biderman

我更早看到过 GitHub Copilot 的影响，后来是 ChatGPT，再到 agentic 能力。大家都在期待，这条线会继续上升，但我觉得真正质变还没全部出现。

Jessy Lin

我同意，变化并非完全不确定，它现在更多是以个人和经济可用的方式快速更新。

Dan Biderman

我们还在观察模型是否在 on-the-fly 学习上变得更安全、有用。我认为未来会看到更多。

Sonya Huang

另一个思路是‘token 钱包’：我们会把模型记忆像钱包一样带到不同公司、应用和工作空间。你认为会出现可跨平台的 memory bank 吗？

Jessy Lin

方向值得关注，但我个人希望个人与工作上下文仍可隔离。就算是 ChatGPT 记忆，也不想把‘上周训练的 GPU 话题’直接带到工作场景。

Sonya Huang

对。

Jessy Lin

我理解它的价值，但更想要的是可控、可分离的记忆边界。用户希望工具里的记忆有明确权限和场景隔离。

Dan Biderman

理想状态是你在工作中消耗大量 token 创造价值，企业保留知识产权，个人也能带走一部分可迁移技能。就像生物学里有 NDA、伦理边界一样，数字世界可能会形成更细的授权协议。

Shaun Maguire

我在斯坦福 2007 做 PhD 时 AI 很枯燥，几乎全是统计学习；当时主要是 CV 和 NLP。你会不会觉得语言会不会被视觉取代？后者还有机会吗？

Jessy Lin

我自己对语言一直有偏好。语言承载了大量抽象表达，我认为短期内文本和语言体系会更易形成统一的抽象表示，未来视觉和语言也会融合成一个多模态系统。

Dan Biderman
