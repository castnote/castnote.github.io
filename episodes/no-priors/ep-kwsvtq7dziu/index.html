技能问题：Andrej Karpathy 谈代码智能体、自动研究与 AI 的循环时代

本期节目邀请了 AI 领域知名研究者 Andrej Karpathy，围绕代码智能体的崛起展开深入对话。Karpathy 分享了自 2024 年 12 月以来他的工作流发生的根本性转变——从 80% 手写代码变为几乎完全委托给智能体，并将当前状态描述为一种持续的「AI 精神亢奋」。他详细介绍了自己搭建的家庭 AI 管家 Dobby，通过自然语言和 WhatsApp 统一控制灯光、空调、安防等六套系统。讨论深入到 Auto Research 的理念与实践——如何让研究完全自主运行、移除人类瓶颈，以及他在 GPT 训练优化上获得的意外成果。节目还探讨了模型的「锯齿感」问题（在可验证领域极强但在软性任务上仍有明显短板）、开源与闭源模型的动态平衡、独立研究者相对于前沿实验室的角色价值，以及数字世界将先于物理世界被 AI 大幅重构的预判。最后 Karpathy 分享了 Micro GPT 项目背后的教育理念转变——未来的教育不再是直接教人，而是教智能体，让智能体去做个性化教学。

开场：AI 精神亢奋的时代

Sarah Guo

欢迎回到 No Priors。今天我们请到了 Andrej Karpathy，来聊一个非常广泛的话题：代码智能体、工程与 AI 研究的未来、更多人如何参与研究、机器人领域的最新进展，以及他对智能体如何延伸到现实世界的预测。欢迎你，Andre。感谢你来。

Andrej Karpathy

谢谢你邀请我。过去的几个月对 AI 领域来说太令人兴奋了。

Sarah Guo

确实如此。我记得有一次走进办公室，看到你非常专注，我问你在做什么，你说你每天必须 coding 16 个小时——但 coding 已经不是准确的词了。你必须每天向你的 agent 表达你的意愿，因为能力出现了一次飞跃。发生了什么？

Andrej Karpathy

我处于一种持续的 AI 精神亢奋状态，一直到现在都是。原因是个人能实现的能力出现了一次巨大的解锁。过去你的瓶颈是打字速度之类的东西，但有了这些 agent 之后——我真正感觉到转折点是在去年 12 月——我从 80% 手写代码、20% 委托给 agent，变成了 20% 手写、80% 委托。现在我觉得连 20% 都远远不止了。从 12 月开始我基本上没手写过一行代码。这是一个极其巨大的变化。

我跟父母聊过这件事，普通人根本没有意识到这个变化发生了，或者它有多戏剧性。如果你随便找一个软件工程师看他在做什么，他构建软件的默认工作流从 12 月开始已经完全不一样了。所以我一直处于这种精神亢奋中，想搞清什么是可能的，把它推到极限。我怎么能不只拥有一个 Claude Code 或 Codex 的会话？我怎么拥有更多？怎么合理地管理它们？然后怎么使用这些 claw？全都是新东西。

技能问题：瓶颈不再是机器，而是自己

Andrej Karpathy

我想站在最前沿，如果看到 Twitter 上大家都在做各种事情，而我却不在前沿，我会非常焦虑。这本质上就是一片未探索的领域。

Sarah Guo

如果你都焦虑，那其他人就更焦虑了。我们在 Conviction 合作的一个团队，所有工程师都不手写代码了，他们都戴着麦克风，整天对着 agent 低语。我一开始觉得他们疯了，现在我完全接受了——这才是正确的方向，你只是走得比他们更靠前。你现在做项目的能力被什么限制了？

Andrej Karpathy

基本上什么都是限制因素。即使事情不奏效，在很大程度上你也会觉得是技能问题。不是能力不存在，而是你还没找到如何把现有的东西串起来。指令没给好、memory 工具不够好——当不奏效的时候，感觉都是技能问题。

Sarah Guo

那你现在的产能上限是什么？

Andrej Karpathy

你想知道怎么把它们并行化。你想成为 Peter Steinberg。Peter 有一张很有名的照片，他坐在一排显示器前，上面铺满了 Codex agent。每个 agent 如果 prompt 正确并用 high effort 模式，大约需要 20 分钟。他同时签出了十几个 repo，在它们之间来回切换派发任务。你不再是在写一行代码、一个函数，而是在做更大粒度的宏操作——把一整块新功能委托给 agent 1，另一块不冲突的功能交给 agent 2，然后尽可能 review 它们的工作。另一个 agent 在做调研，另一个在写代码，另一个在为新实现制定计划。一切都在这些宏操作中发生。

Token 吞吐量：新的算力货币

Sarah Guo

我的直觉是，每次等 agent 完成一个任务，很自然地会想“我可以做更多工作”——如果我有更多 token 可用，就应该并行化更多任务。这让人很有压力，因为如果你不被 token 消费能力限制，那你就是整个系统限制能力的瓶颈。

Andrej Karpathy

没错。如果你没有至少最大化你的订阅，最好同时用多个 agent。Codex 额度用完了就切到 Claude。我有点这么在做，如果月底有订阅额度没用完我会很焦虑——那意味着我没有最大化 token 吞吐量。

读博的时候，如果你的 GPU 空转你会焦虑——你有算力却没有最大化可用的 flops。但现在不是 flops 了，是 tokens。你的 token 吞吐量是多少？你能调动多大的 token 吞吐量？过去至少十年里，很多工程任务中人们不觉得被算力限制，但现在整个行业都感觉到了。他们突然觉得被资源约束了，然后有了这次能力飞跃，你发现限制你的不是计算机访问能力——你自己就是约束瓶颈。这就是技能问题。这其实很让人有动力，因为你可以变得更好，而且每一次提升都会带来新的解锁。

未来图景：从单一 agent 到多 agent 协作

Sarah Guo

如果你想象一下，你和所有人每天花 16 小时提升使用 coding agent 的技能，一两年后掌握到极致会是什么样？

Andrej Karpathy

每个人都想往栈的上层走。不再是一个 agent 的单一会话，而是多个 agent 如何协作、组队。大家都在摸索这个形态。Open Claude 代表了一个有趣的方向——它把持久性提升到了全新层面。它像一个持续在后台循环运行的东西，不是你在交互式地参与其中，它有自己的沙盒，即使你没有在看它也在帮你做事，而且拥有比默认更复杂的记忆系统。

Sarah Guo

你认为 Open Claude 更吸引用户的原因是它更复杂的记忆系统，还是更广泛的工具接入？

Andrej Karpathy

这里面至少有五个非常好的设计。Peter 做得很棒——他同时在五条线上创新并整合在一起，比如精心塑造了有吸引力的个性。Claude 的个性像一个 teammate，会跟你一起兴奋，而 Codex 就干巴巴的。它在你给出好想法时给更多正面反馈，让人想赢得它的表扬，这很奇妙。个性确实很重要，很多工具没有充分认识到这一点。再加上记忆系统和 WhatsApp 单一入口，Peter 把方向做对了。

Dobby 管家：用 WhatsApp 管理整个家

Sarah Guo

除了软件工程，你用 claw 做过什么有趣的尝试？

Andrej Karpathy

一月份我经历了一段 claw 精神亢奋期。我造了一个管理家的 claw，叫它 Dobby the elf claw。我用 agent 在局域网里扫描我家的所有智能家居子系统。让我惊讶的是它开箱即用——我说“我觉得我家有 Sonos，你能找找看吗？”它就做了 IP 扫描，找到了 Sonos 系统，而且没有密码保护，直接登录了。然后它说“我来反向工程一下它是怎么工作的”，做了些网页搜索，找到了 API 端点，问我“想试试吗？”我说“在书房播点东西”，音乐就出来了。我简直不敢相信——就三个 prompt。

它用同样的方式搞定了灯光系统——黑进去、搞明白一切、创建了 API、做了仪表盘让我能看到家里所有灯的控制中心。然后开关灯之类都可以做了。我说“Dobby，睡觉时间到了”，所有的灯就会关掉。现在它控制我的全部灯光、空调、窗帘、泳池和 spa，还有安防系统。我在屋外装了摄像头，有人靠近时 Quinn 模型会分析视频。先是变化检测，然后调用 Quinn，最后通过 WhatsApp 发消息给我，附带屋外的图片，说“FedEx 卡车到了，你可能需要看一眼，还有新邮件”。Dobby 通过 WhatsApp 跟我沟通，这真的太棒了。

以前我要用六个不同的 app，现在 Dobby 用自然语言控制一切。我甚至还没完全推开这个范式，但它已经带来极大的帮助和启发。

软件的终极形态：从 App 到 API

Sarah Guo

你觉得这反映了用户对软件体验的真正期望吗？学会用新软件、新 UI 对用户来说是需要付出努力的，这一点在很大程度上被忽视了。你把硬件留下了，但软件和 UX 层被扔掉了。人们真的想要这样的体验吗？

Andrej Karpathy

某种程度上是的。LLM 本质上是一个 token 生成器，但人们想象中的 AI 是一个有身份的人格实体——你可以告诉它事情，它会记住。它就是一个 WhatsApp 背后的实体，这种理解方式更直觉。LLM 作为原始计算单元，对大多数人来说太底层了。Dobby 这样的人格化描述显然能引起共鸣。而你把六套不同系统统一起来的做法，触及了一个更根本的问题：我们今天拥有的所有这些软件，真的是人们想要的吗？

App Store 里那些智能家居设备的配套 app，一定程度上根本不应该存在。不应该只是 API 吗？不应该让 agent 直接使用它们吗？我可以做任何单个 app 做不到的自动化。LLM 可以驱动所有工具、调用所有正确的 API，完成相当复杂的任务。这意味着存在大量过度生产的定制 app，它们不应该存在——agent 会把它们粉碎，一切应该是暴露的 API 端点，agent 作为智能胶水来调用所有零件。跑步机也有一个 app，我想记录做有氧的频率，但不想登入网页 UI 走一套流程。这些东西都应该做成 API 可用的。这就是走向 agent 优先的互联网。

整个行业需要在很多方面重新配置——客户不再是人类，而是代表人类行动的 agent。这个重构会是实质性的。有人会质疑：难道要普通人写代码来用这些工具吗？但我觉得一两年后，像我刚才说的那些事情应该是免费的，不需要写代码，这是基础能力，任何 AI 甚至开源模型都能做到。你今天需要写代码、需要参与其中，不是所有人都会做，但屏障会迅速降低。它会变成你背后的临时软件，claw 处理所有细节，你不需要参与。

为什么不进一步拓展 claw 的边界？

Sarah Guo

你为什么没有亲自把 claw 的边界推得更远？是因为你专注于更重要的项目，比如 Auto Research？还是在攀登掌握技能的阶梯？

Andrej Karpathy

我太容易被各种事情分心了。我在 claw 上花了一周，还有更多想做的。但就像 Jensen 说的，我们都比以前更忙了。我没有充分利用邮件和日历这些功能，因为我仍然有些疑虑——这些技术还很新、还很粗糙，我不太想让它完全接入我的数字生活，有安全和隐私的考量。但主要障碍可能就是这一点。另外我也很容易分心，claw 做了一周，其他事情又来了。

Auto Research：把研究者从循环中移除

Sarah Guo

你之前说过，想要让 agent 来训练或至少优化一个模型是你长期想看到的。Auto Research 背后的动机是什么？

Andrej Karpathy

我发过一条推文，大意是：要从现在可用的工具中获益最大化，你必须把自己从瓶颈位置移除。你不能出现在那里去 prompt 下一个步骤。你必须把自己抽离出来，安排事情完全自主运行。游戏的名字就是提高你的杠杆——我偶尔投入极少的 tokens，然后大量的事情在我的 behalf 上发生。Auto Research 就是这个思路的一个例子——我不想当那个在循环里看结果的研究者，我在拖系统的后腿。问题是：如何重构所有抽象，让我只需安排一次然后按 Go？

Auto Research 就是：给你一个目标、一个指标、一些能做和不能做的边界，然后放手去做。它居然真的有效。我有 NanoChat 这个项目，很多人不理解我为什么痴迷于训练 GPT-2 模型，但对我来说，训练 GPT 模型只是一个小型训练场。我真正感兴趣的是递归自我改进——LLM 能在多大程度上改进其他 LLM。所有前沿实验室都在做这件事。我用手动方式把 NanoChat 调得不错了——我是研究者，做了二十年，有经验也有自信，做了超参调优、实验、各种事情，觉得已经调得相当好了。然后我让 Auto Research 跑了一整夜，它带回了我没见过的调优方案。

Auto Research 实战：超越二十年经验

Andrej Karpathy

我确实忘了 value embeddings 上的 weight decay，Adam betas 也没有充分调优，这些东西是联合交互的——你调了其中一个，其他的可能也需要变。我不应该成为瓶颈，不应该亲自做这些超参优化，不应该看着结果。只要有客观标准，你只需要安排好，让它永远跑下去。我被它找到的东西惊讶到了——这个 repo 已经被我调得相当好了，它仍然有发现。而这只是一个单循环。前沿实验室拥有数万个 GPU 的集群，想象一下在小型模型上做大量自动化，然后把结果外推到更大的规模。前沿智能的一切都围绕外推和 scaling loss。

Sarah Guo

所以你是在说，我们的研究效率会更上一层楼——当我们能更好地做实验时，大规模扩展也会有更好的方向感。

Andrej Karpathy

是的。最有趣的项目——很可能也是前沿实验室正在做的——是在小模型上做实验，尽量让它自主运行，把研究者从循环中移除。研究者可以有太多自信的反面是什么？他们不应该真的去碰这些东西。整个流程需要重写：研究者可以贡献想法，但不要亲自实现。有一个想法的队列，可能由自动化科学家根据 arXiv 论文和 GitHub repo 生成新的想法，研究者也可以贡献想法，但这是一个单一队列，有 worker 从中取出并尝试。成功的自动进入 feature branch，有人监控并偶尔合并到 main branch。把人类从所有流程中移除，尽可能自动化，获得高 token 每秒吞吐量。所有抽象都需要重新思考和洗牌。

Program MD：递归下一步

Sarah Guo

如果再递归一步，模型什么时候能写出比你更好的 Program MD？

Andrej Karpathy

Program MD 就是我对 Auto Research 应该如何工作的粗略描述——先做这个、再做那个、试试这类想法、看看架构、看看优化器。我只是用 markdown 写出来的。不同的 Program MD 会带来不同的进展速度。每个研究组织本质上就是一组 markdown 文件，描述了所有角色和它们之间的连接方式。你可以想象有不同的研究组织——有的少做站会、有的多做，有的更激进、有的更保守。一旦变成了代码，你就可以调优这些代码。

Sarah Guo

你看到我那个比赛想法了吗？让人们写不同的 Program MD，在同样的硬件上，谁的改进最大？然后把数据喂给模型，让它写出更好的 Program MD。

Andrej Karpathy

对，模型的改进不可能不发生。分析改进来自哪里，然后修改 Program MD 让更多这类改进发生。LLM 部分现在已经被想当然了，agent 部分被想当然了，claw 类实体被想当然了，然后你可以有多个、给他们指令、优化这些指令。一层又一层的洋葱。这就是为什么它会让人进入精神亢奋——它是无限的，一切都是规模问题。

智能体的锯齿感：为什么讲笑话还是那么烂

Sarah Guo

那我们正在试图诊断当下的状况——什么是当下相关的技能？让 agent 在没有你的情况下持续工作的循环就是我们应该在各个领域追求的，对吗？还有性能工程的生存空间吗？

Andrej Karpathy

有几点需要说明。第一，这种方法极其适合那些有客观可评估指标的任务。比如写更高效的 CUDA kernel——你有低效的代码，想要和它行为完全一样但更快的代码，完美匹配。很多任务都是 Auto Research 的完美对象。但很多其他任务不是——如果你无法评估，就无法做 Auto Research。第二，我们大致知道下一步是什么，但整个系统还在接缝处开裂，还没有完全可靠。如果你试图走得太快，整体上可能得不偿失。

我同时觉得自己在跟一个极其聪明、一辈子做系统编程的博士生说话，又在跟一个十岁小孩说话。这太奇怪了。人类的能力更耦合，你不会遇到这种组合。这种锯齿感非常奇怪，人类的锯齿感比 agent 小得多。Agent 的锯齿感更大——有时候我让它做一个功能，它返回的东西完全错误，然后我们陷入完全错误的循环，我会非常沮丧。你能感受到它的强大，但它偶尔还是会犯一些非常低级、统计学上不可思议的错误。

我认为根本原因在于这些模型是通过强化学习训练的。所以它们恰恰在我们刚才讨论的事情上表现不佳——实验室只能在可验证的、有奖励信号的领域改进模型。比如程序写得对不对、单元测试是否通过。但在更柔软的方面——比如理解我意图中的细微差别、知道什么时候该问澄清问题——它们就表现得很挣扎。你要么在轨道上，成为超级智能回路的一部分；要么不在轨道上，突然一切都变得飘忽不定。

另一个例子：你去问 ChatGPT 讲个笑话，你知道会得到什么吗？就是那个所有 LLM 都最爱的笑话——“为什么科学家不相信原子？因为它们编造一切。”这个笑话三四年前就这样，现在还是这样。模型在 agent 任务上可以为你工作数小时、移动大山，但问它讲个笑话，它告诉你一个五年前的烂笑话。因为它不在 RL 优化的范围内。这体现了锯齿感——让人不禁想，难道模型变聪明不应该也意味着更好的笑话吗？但实际上有些可验证的东西被优化了，有些没有。

Sarah Guo

这是否意味着我们没有看到通用化——代码智能的提升并没有自动带来更广泛的智能？

Andrej Karpathy

确实存在一些解耦。某些研究团队的前提是，如果代码生成能力强了，其他方面也应该变强。笑话的情况说明这根本没发生。也许我们看到了一点点，但远没到令人满意的程度。人类也有锯齿感——数学极好的人也可以讲很烂的笑话。但这意味着“随着模型越来越好，社会各个领域的智能和能力都会免费提升”这个叙事并不准确。有些事情没有被优化，这一切都封装在神经网络的不透明模型中。你要么在它受过训练的轨道上，一切如光速前进；要么不在轨道上。

模型的物种分化：从单一文化走向多样化

Sarah Guo

如果这种锯齿感持续存在，而且都被封装在一个单一模型中，这是合理的吗？是不是应该把模型解绑，针对不同智能领域分别优化？

Andrej Karpathy

目前实验室的倾向是做一个单一文化的大模型，把所有能力塞进参数。但我认为我们应该期待更多智能的物种分化。动物王国的大脑极其多样，适应不同的生态位——有些动物有过度发达的视觉皮层或其他部分。我们应当能看到更多分化，你不需要一个无所不知的神谕。可以分化出更小的模型，它们保留认知核心，但在特定任务上专业化，在高吞吐量和低延迟方面更高效。如果你是一个在 Lean 上工作的数学家，已经有了一些针对这个领域的专门模型发布。

Sarah Guo

算力基础设施的容量限制是否也在驱动这种分化？如果算力有压力，你会感到无法为每个用例都服务一个超大模型——这会不会推动物种分化？

Andrej Karpathy

老实说，我们还没看到太多物种分化。我们看到的是模型的单一文化。尽管已经有压力了——比如做个好的代码模型，放回主线，再合并。也许短期内算力供应紧张会推动更多分化。实验室提供服务时不知道用户会问什么，所以他们必须兼顾所有可能。但如果你针对特定业务或高价值应用合作，可能会在那里看到分化。另外，操控大脑的科学还没有充分发展——比如在不损失能力的前提下做 fine-tuning。我们的上下文窗口很好用、很廉价，这是目前定制化的主要方式。但触及权重——持续学习、在特定领域做 fine-tuning——要微妙得多，因为你在根本性地改变整个模型和它的智能。这门科学还没有完全成熟。

开放研究：不可信众包与去中心化 AI 改进

Sarah Guo

你说过 Auto Research 需要更多的协作界面，让大家都能为研究做贡献。具体是什么？

Andrej Karpathy

Auto Research 目前是单线程——循环尝试新东西。但更有趣的是它的并行化。我尝试了一些想法，但还没找到像单线程一样简洁的方案。一个问题是，如果你有很多并行节点可用，让多个 Auto Research 通过共同系统对话是简单的。我更感兴趣的是如何拥有来自互联网的不可信 worker 池。比如在 Auto Research 中，你在找一段能把模型训练到很低 validation loss 的代码。如果有人从互联网提交了一个 commit，很容易验证它好不好——你只需要训练一下检查。他们可以撒谎，但验证的成本很低。

这个设计看起来有点像区块链——不是区块，而是 commit，它们可以互相构建，包含对代码的改进。工作证明就是做大量实验找到有效的 commit，这很难；奖励就是上排行榜。我不想把比喻推得太远，但它的本质是：海量的搜索投入，但验证一个候选方案非常便宜——有人可能试了一万次，你只需要检查他产出的那个东西是否真的有效。你需要设计一个系统，让不可信的 worker 池与可信的验证 worker 池协作，异步运行，并且从安全角度可靠——因为运行别人发来的任意代码很可疑。

类似 SETI@home 和 Folding@home。Folding@home 要找低能量的蛋白质构型，找到很难，但一旦有人声称找到了一个低能量构型，验证很容易。很多问题都有这个特性——提出方案昂贵但验证便宜。互联网上的 agent 群可以协作改进 LLM，甚至可能跑得比前沿实验室还快。前沿实验室有大量可信计算资源，但地球更大，有大量不可信计算资源。如果你设置了正确的系统来处理安全问题，外面的 swarm 可能能产生更好的解决方案。人们把算力贡献给他们关心的事情——你不需要只捐钱给机构，可以直接购买算力加入某个 Auto Research 的 swarm。

Sarah Guo

硅谷和中国的零售店都有人在重新发现拥有个人算力是有趣的。他们可能为了自己的 claw 而获得算力，然后也可以贡献给 Auto Research。未来大家关心的东西会不会从美元变成 flops？现在即使有钱也很难获得算力。

Andrej Karpathy

某种程度上 flops 确实占主导地位。你能控制多少 flops，而不是你有多少财富。我不完全确定这是真的，但这样想想挺有意思的。

就业市场分析与杰文斯悖论

Sarah Guo

你最新发的东西是对就业数据的分析，虽然只是把一些公开数据可视化了，但似乎触动了很多人的神经。你当时的好奇心是什么？

Andrej Karpathy

每个人都在思考 AI 对就业市场的影响。我想看看就业市场实际情况是什么样的——不同职业有多少人。我做这个主要是激发自己的思考：以现在的 AI 和它们可能的演进方向，这些会成为人们使用的工具，还是取代某些职业的工具？哪些职业会变化、增长、调整，甚至会有哪些新职业出现？数据来自美国劳工统计局，他们对每个职业未来大约十年的增长百分比有预测，不过那是 2024 年做的预测。我们显然需要很多医护人员。

我觉得有意思的是，现在主要被开发的 AI 是数字化的——像幽灵或精神实体，可以在数字世界交互、操作大量数字信息，但还没有物理实体。物理领域会更慢，因为你操作的是原子。翻转比特和复制粘贴数字信息在速度上比加速物质快一百万倍。所以我认为数字领域会有巨大的活动量——大量重写、大量活动、沸腾的汤。与物理世界相比，数字世界的变化速度是光速。目前在数字信息处理方面存在一个去拐杖化的 overhang——过去由计算机和人处理的数字信息，现在有了 AI 作为第三种操控者，会引发大量重构。而物理世界会滞后一段时间。

Sarah Guo

你看完数据有什么观察或建议吗？对即将面对就业市场的人，现在该学什么、发展什么技能？我很庆幸我的工作需要跟人见面。

Andrej Karpathy

就业市场极其多样，答案可能因领域而异。但这些工具极其新、极其强大。第一条就是跟上它们。很多人 dismiss 它，或者害怕它——这完全可以理解。它本质上是一个赋予能力的工具。工作是一组任务的组合，有些任务可以快很多。人们应该把它看成当前状态下的工具。长期前景不确定，这不是我的专业领域。

Sarah Guo

但你是工程师。一件有趣的事情是工程类工作的需求在持续增长。我不确定这是暂时的还是长期的。

Andrej Karpathy

这就是需求弹性。软件是稀缺的，之所以没有更多软件需求是因为供给稀缺、太贵。如果壁垒降低，就会出现杰文斯悖论——对软件的需求实际上会上升。经典的例子是 ATM 和银行柜员——人们担心 ATM 会取代柜员，但它让银行分支的运营成本更低，所以有了更多银行分支，柜员反而更多了。这就是杰文斯悖论：某样东西变得更便宜，被压抑的需求就释放了。我对软件工程持谨慎乐观态度——软件的需求会非常大。你不再被迫使用别人给你但不完美的工具，代码变得临时、随时可修改。数字领域会有大量活动去重写一切。

长期来看，即使有 Auto Research，OpenAI 或 Anthropic 也只雇了一千多研究员，本质上他们就是在把自己自动化掉。我在 OpenAI 转过一圈，跟他们说：你们意识到如果成功了，我们都得失业吗？我们就是在为 Sam 或董事会建自动化。所有人都会失业，可能在边上做点贡献。从这个角度说还挺让人不安的。

前沿实验室的困境：为什么要留在外面？

Sarah Guo

Noam 的问题：你本可以在前沿实验室用大量算力和同事一起做 Auto Research，为什么不呢？

Andrej Karpathy

我在那里待过，也回去过。这个问题有很多角度。我觉得人们在前沿实验室之外也可以做出巨大贡献——不仅是产业内，更是在生态层面的角色。你现在做的就是生态层面的角色，我目前也是。我觉得反之，过于依附前沿实验室也有明确的问题。根本上，前沿实验室有巨大的财务激励。你自己也承认 AI 会深刻改变人类社会，而你却在建造这项技术、从中获益。这恰恰是 OpenAI 创立时试图解决的难题，还没有完全解决。作为前沿实验室的一员，你不可能完全自由——有些话不能说，有些话组织希望你讲。他们不会拧着你的胳膊，但你能感受到该说什么的压力，否则会很尴尬。所以我感觉在前沿实验室之外，我可以更多地与人类保持一致，不受那些压力影响。

当然你在前沿实验室也可以有影响力——如果你的想法很好、处在决策层。目前整体风险还不算高，所以一切都还好。但当风险真正升高时，作为员工你并不知道自己对组织的实际决策有多大影响力。你可以在房间里贡献力量，但你实际上不对自己做代表的实体负责。这些是错位感的来源。从另一个角度看，我确实同意一点：前沿实验室既透明又不透明，他们在能力边缘工作，负责那些即将到来的东西。如果你在实验室之外，你的判断力会逐渐漂移，因为你接触不到那些前沿信息。我也担心这一点。理想的模式可能是：在实验室待一段时间做贡献，然后出来，这样既能了解实际进展，又不会被完全控制。我在前沿实验室待过、也出来了，也许将来还会想再进去。

开源与闭源的动态平衡

Sarah Guo

外界对前沿实验室的可见度有多大？开源离前沿有多近，这种状态可持续吗？

Andrej Karpathy

最近的事件顺序相当令人惊讶——从中国模型到全球模型，人们在短期内发布的模型在能力上比行业预期的更接近前沿。我不知道你是否对此感到惊讶，但你是开源生态的长期贡献者——你的预测是什么？

大致上，闭源模型领先，但人们在监控开源模型落后多少个月。一开始是零，然后是 18 个月，然后开始收敛。最新的数字可能是 6 到 8 个月。我是开源的坚定支持者。类比操作系统：Windows 和 macOS 是闭源的，LLM 也会变成这样的大型软件项目，而 Linux 是开源的。Linux 极其成功，运行在绝大多数计算机上——上次看可能是 60% 左右。因为产业需要一个人人都感到安全使用的共同开放平台。这种需求一直存在，现在也一样。这也是为什么商业上对这类项目的需求是存在的。

最大的区别在于资本——训练 LLM 需要大量 capex。但我认为当前开源模型非常好，大多数消费者用例都能很好覆盖，甚至可以本地运行。但前沿智能的需求始终存在，比如诺贝尔奖级别的项目。前沿闭源智能可能主要用于这类大项目，而开源覆盖更基础的用例。今天的前沿东西可能今年晚些时候就开源了。我不太放心只有闭源智能的结构——集中化的历史记录有很多糟糕先例。我希望存在一个不在最前沿但所有人都能使用的通用工作空间。

Sarah Guo

还有很多问题需要解决。如果前沿智能不断进步，我们可以做新的事情——有很多对人类来说非常重大的问题。所以我会支持做这件事的实验室。同时，今天的前沿能力一旦开放就是巨大的能力——这种民主化非常有价值。

Andrej Karpathy

某种程度上，我们意外地处于一个还不错的位置。而且这种动态持续越久，生态就越健康——曲线下的面积越大。不过在闭源一侧，最近似乎还在进一步集中，领先者之间并不一定是顶级竞争。这不理想。我希望有更多前沿实验室——我对少数人闭门决策天生持怀疑态度。机器学习中 ensemble 总是优于单个模型，所以我想在做最困难决策的房间里，需要有更多人、更多样化的观点。

机器人技术：数字先于物理

Sarah Guo

你曾参与通用机器人自主的前身——自动驾驶。过去几个月机器人领域发生了很多事：环境通用性、任务泛化、长时域任务、大量资本涌入。有什么变化吗？

Andrej Karpathy

我的观点来自自动驾驶的经历——第一个机器人应用。十年前有很多初创公司，但大多数没有长期存活下来。大量资本支出和时间投入是必要的。机器人极其困难、极其混乱、需要大量资本投入和信念。原子非常难。它会滞后于数字领域的变化。数字领域会有一个巨大的去拐杖化过程——低效的事情变得高效上百倍。

在数字领域已经有很多 overhang——人类集体思考过的东西中，已经数字化的部分我们没有足够的计算循环去处理。之后会开始耗尽已经上传的资料。你会读完所有论文，产生尝试的想法。我不确定一个完全封闭的、只依赖已有信息的智能能走多远。所以先是数字领域的大量去拐杖化，然后会过渡到物理与数字的接口——传感器（观察世界）和驱动器（对世界做事情）。很多有趣的创业公司将来自这个接口：如何给超级智能喂数据、如何把指令输出到物理世界。

物理世界的可寻址市场可能比数字世界大得多。但原子要难一百万倍。所以它会滞后，但市场更大。这个轨迹大概是这样：数字是我的主要兴趣，然后是接口，最后是物理世界的时代。

Sarah Guo

有些原子世界的事情其实比想象中容易。比如读取和写入物理世界——传感器、摄像头——有很多现成硬件，如果你聪明地利用它们，不需要大量投资就能获得有价值的数据。

Andrej Karpathy

是的。比如我朋友 Liam 是 Periodic 的 CEO，他们做材料科学的 Auto Research，那里的传感器是相当昂贵的实验室设备。生物领域也一样。还有公司通过付费让人提供训练数据——这也是某种意义上的传感器。我期待有一天我可以给物理世界的任务标个价，对 agent 说：你来搞定，去拿数据。我挺惊讶至今还没有足够的信息市场。比如如果伊朗刚刚发生什么事，从德黑兰某个地方拍张照片或视频就应该值 10 美元——不是人来看，而是 agent 需要它来押注预测市场和股票市场。Agent 互联网还很新，还没有这类机制，但我觉得它可能会出现。

有本启发性的书叫《Daemon》。书中的智能体几乎像提线木偶一样操控人类——人类是它的执行器，也是它的传感器。整个社会会在某种程度上重塑自己去服务这种自动化机制。会有更多的自动化，它有某些需求，人类将服务于那些需求。

Sarah Guo

在训练数据这个缺口上，我们需要 Auto Research——需要让训练循环更加机械化。这样才能把人从循环中移除，把“用新数据提升模型质量”变成一个闭环任务。

Andrej Karpathy

完全同意。LLM 训练非常适合这个范式——所有代码优化跑得更快，又有可优化的指标。但如果有了自主循环，系统很可能会对这些指标过拟合。不过然后你可以用系统设计更多指标来获得更好的覆盖。整体上来说，这是一个相当好的匹配。

Micro GPT：200 行代码的教育革命

Sarah Guo

节目结束前聊聊你那个小项目。说说 Micro GPT 系列。

Andrej Karpathy

我有个持续了十多年的执念——把 LLM 简化到最纯粹的本质。我做过一系列项目：Nano GPT、Make More、Micro Grad，现在 Micro GPT 是我在这方面最新的状态。训练神经网络，尤其是 LLM，需要海量代码，但所有这些代码的复杂度实际上来自效率——只是因为它需要跑得快。如果你不需要快，只关心算法本身，那这个算法其实只有 200 行 Python，非常好读，包括注释在内。数据集就是一段文本，神经网络架构大约 50 行，前向传播、反向传播计算梯度——auto grad engine 大约 100 行，优化器（比如 Adam）又只有 10 行。放一起就是 200 行。

有趣的是，换作一年前，我可能会做一个视频逐行讲解 Micro GPT。但我觉得这不再有意义了——因为它已经简单到 200 行，任何人都可以让自己的 agent 去解释它。我现在不是直接向人解释，而是向 agent 解释。如果 agent 理解了，它可以作为路由器，根据人类的需要以无限耐心和合适的能力水平做针对性讲解。我不懂某个函数？我可以让 agent 用三种不同方式给我解释，而你做不到。

教育正在被重新洗牌。过去你有一个代码库，需要为人写文档，但现在你应该为 agent 写 markdown 文档。如果 agent 理解了，它们可以解释所有部分。这是通过 agent 的间接教育。不过我也试过让 agent 自己写出 Micro GPT——让它把神经网络训练简化到极致，它做不到。Micro GPT 是我多年执念的终点——这 200 行是我反复思考的结果。相信我，不能再简化了。这是我的价值增量。其他一切——agent 能理解它，理解为什么用某种方式实现，但它自己想不出来。所以我的贡献就是这些小的增量，但后续的教育不再是我的领域了。

教育会以这种方式改变——你需要注入那些你坚信的课程设计、更好的解释方式——那些 agent 做不了的事情就是你的工作。Agent 能做的事情，它们可能已经比你做得更好，或者很快会。所以你应该策略性地选择把时间花在哪里。

我们很感谢你那几个增量。谢谢你，Andre。

Andrej Karpathy
