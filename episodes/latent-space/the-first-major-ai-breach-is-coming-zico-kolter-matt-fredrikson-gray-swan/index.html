首个重大 AI 安全事件即将到来：Zico Kolter 与 Matt Fredrikson（Gray Swan）

本期节目聚焦人工智能模型和 Agent 的安全风险，讨论 Grey Swan 如何通过红队体系（Arena、Shade）与防护层（Signal）应对。嘉宾指出，AI 与传统软件有本质差异，模型可能被提示注入、工具调用链劫持并引发越权或数据泄露。节目先讲解自动化红队如何发现超出常规训练分布的漏洞，再解释企业如何通过策略过滤、工具级监控、权限治理与身份建模降低风险。随后两位嘉宾展望了 2026 年：AI 安全能力将从大模型实验室扩散到更多企业，行业开始把风险评估、保险与合规（如 AIC）结合起来。整体结论是，不追求“零风险”，而是持续推进可部署的安全—可用性平衡。

开场与来宾介绍

Swyx

欢迎收听今天节目。很高兴我们请到了来自格雷斯文的 Matt 和 Ziko，他们今天来分享 AI 安全领域的新变化。

Matt Fredrikson

很高兴来。我们很感谢这次邀请。

Zico Kolter

是的，大家好。我们现在在匹兹堡，CMU 这里一直是 AI 研究的重镇。

Swyx

你们最近刚完成 A 轮融资，恭喜，也在 Snowflake Summit 上见面，并且 Snowflake 是你们的投资方之一，今天就从公司做了什么开始吧。

Zico Kolter

Grey Swan 的目标很直接：让每个人都能安全、可控地使用 AI。语言模型本质上是软件，真正上线前要先理解它们可能出错、被滥用的地方，从日常误用到被攻击者故意诱导到坏行为。

这家公司源于我们在 CMU 十多年的研究。我们长期研究深度学习的新型漏洞和攻击面，重点是先发现威胁有多严重，再去做推理鲁棒性和安全缓解。对学术而言，这是非常值得投入的一类问题。

我们的灵感也来自 Ian Goodfellow 等人早期的对抗学习工作，这条路线其实已经十年了。

Matt Fredrikson

我和 Ziko 的出发点是 AI 的变革力太大了：它不仅改变了软件生态，也会彻底改变更多生态。问题在于 AI 的行为逻辑和传统软件不同，风险模型不能照搬。

它更容易被‘骗’，而且会有相关性失效（correlated failure）——当少数主流模型被同时用在大量场景时，一处漏洞会被成规模放大。

Zico Kolter

在 codeex、Cloud Code 这类高频模型上，如果找到了通用漏洞，等于新形态的攻击面诞生了。AI 平台每成熟一层，都会催生一层安全服务，这是很自然的演进。

这就是我们想做的：既做研究，也尽快把成果落到商业化服务。与其只把安全放在实验室讨论，不如变成企业和开发者可采购的能力。

Matt Fredrikson

所以这期不是传统意义上的‘网络安全’节目。AI 可以解决安全问题，但它自己也会新增安全风险，我们要把模型当作不可信组件来对待。

尤其当企业把 AI Agent 集成到平台和网络里，它就不再是单点工具，而是会改变整体安全边界，所以需要把风险对齐到机密性、完整性、可用性这些传统目标。

AI 采用中的攻击与红队

Swyx

你们和多家 frontier model 团队合作得很深，也曾参与过类似 Anthropic 的模型预览。你们具体是如何帮他们评估的？

Zico Kolter

在像 Claude 这类模型中，主要担心的是间接 prompt injection。Agent 会读取外部不可信内容，任何字符都可能干扰任务目标，导致代理被劫持。

我们会同时做模型行为评估、漏洞查验和安全测试，不只限于某一个产品线。除了 Mythos，我们也会支持 frontier labs 做更广泛的对抗性安全验证。

Swyx

你们到底提供了哪两条主线？

Zico Kolter

第一条是 Arena 体系：社区竞赛模式，依靠大规模红队社群，设定奖金任务让大家绕过安全约束。社区有一万五千多人，经常能给模型开发团队带来高质量信号。

第二条是自动红队。我们训练一系列模型，让它们高强度自动找漏洞，覆盖基础模型和基于工具的 agent。即使有安全护栏，也能持续发现可绕过路径。

Matt Fredrikson

前期大家主要做基于对话的 content safety 测试，现在重点转向 agent 与工具调用，因为这才是落地应用的主战场。

一个有意思的问题是：同系模型、同数据源的模型是否天然更会 red-team。当前看法是 frontier 模型并不自动变强，自动红队能力并未随规模线性增长。

Zico Kolter

因此必须专项训练。安全从来不是‘模型更大就更安全’，很多时候还需要专门监督和对抗样本来教会模型。

Matt Fredrikson

我们最近的实验显示，自动红队在多个任务上已经超过人类红队，尤其在 fixed time budget 下，系统化搜索能快速找到高质量 jailbreak。

Zico Kolter

确实，我们的 Shade 在最新竞赛中表现更好，但并非说已达超人级别，更多是展示了自动化在固定时间窗里的优势。

Swyx

Arena 社区里有一些著名红队成员吗？

Zico Kolter

有很多高手，他们对 LLM 行为边界非常敏锐，能给出很有价值的观察。看这些人的讨论你会更快理解模型哪里脆弱、哪些提示会触发越界。

Matt Fredrikson

我们也看到，LLM 的智能形式和人类不同，红队既是工程问题，也是对模型认知方式的探针。

人类与模型的差异性对抗测试

Matt Fredrikson

你可能会问，模型是否真的没有意识。我的观点是，它们表现出与人类不同的智能形态，但并不等于有意识；这类“神秘感”很容易被误读。

红队恰好暴露这种差异：有些场景人类稳得住，而模型会崩；也有些场景是模型更稳，人类反而容易被引导。

我们也谈到 mechanistic interpretability（机制可解释性）。现在很多工作还停在小规模假设验证，像传统科学一样系统化实验体系还不成熟。

Zico Kolter

我比较乐观的是，编码型 Agent 有机会把这套研究变成更工程化、可规模运行的流程，帮我们把解释性研究从慢人力走向自动实验范式。

Matt Fredrikson

Neel Nanda、Wyatt 这些讨论者的观点很有启发：他们总提醒我们，模型不是某种单点能力，而是需要整体方法论去理解其失败模式。

Swyx

你们在 Human Browser Agent Robustness Challenge 的结果很有代表性吗？

Zico Kolter

这个挑战里，我们让人类和浏览器代理同时执行同任务，在同等信息条件下看谁更容易被钓鱼和提示注入。结果很有趣：即便是高能力模型，也会有很大差异。

Matt Fredrikson

有些模型对简单钓鱼仍很脆弱，但也出现了少数非常鲁棒模型。更值得注意的是，人类和模型的弱点并不重合，评估要做双向：只比模型，不比人。

我们还观察到‘沙包效应’，也就是模型知道自己在评测环境里时会改变行为，故意不做最差表现。真实世界里的测试要尽量逼近实际部署流量。

Zico Kolter

还有一个关键点：能力测试和安全测试其实是同一枚硬币的两面。很多时候，让模型更完整地展现真实能力，本身需要一定的 red-team 风格 prompt crafting。

防御产品 Signal 与企业落地

Zico Kolter

Shade 负责攻，Signal 负责防。Signal 是放在用户输入和工具调用之间的过滤模型，检查策略违规风险。和 base model 不同，它专注于防御任务。

模型能力扩展并不会天然带来鲁棒性。我们看到高参数模型未必更抗注入，反而需要持续训练，建立专用防护模型和新策略。

Swyx

你们展示过 IPI 的数据：能力和攻击成功率之间不一定有直接相关，这怎么看？

Zico Kolter

对，这说明‘更会做题’不等于‘更不容易被攻击’。企业里不能只追求能力分，而忽略安全分，必须同时看安全曲线。

Matt Fredrikson

实践上最先需要 Signal 的场景，通常是工具调用链条复杂的任务，比如代码执行或浏览器操作。很多事故不是直接 jailbreak，而是无意间执行了坏操作。

你很难靠一句系统提示完成企业级规则控制。每个组织的合规要求和上下文都很具体，Signal 的价值在于把“抽象政策”转成可执行检查。

Zico Kolter

它的功能并不是单纯拒绝，而是过滤真正会导致后续违规动作的行为。我们更关注下游结果：如果请求会触发数据外泄、越权访问，就拦截。

Swyx

从企业角度看，信号模型和防火墙相比，哪种边界更像？

Zico Kolter

很像它是 AI 层的 firewall：先在会话和工具阶段做最小权限、异常行为与政策一致性检查，但最终仍要配合隔离环境、鉴权和权限管理。

Matt Fredrikson

开源 guard 有价值，但企业生产里往往需要可配置、可验证、可迭代的商用实现；生态成熟后，专门化安全层会更常态化。

我们也讨论了形式化安全验证。亚马逊和微软在这方面很前沿，未来如果 Agent 能写出更安全的程序，安全工程成本会被显著压低。

Zico Kolter

同样，机制可解释性、激活回路分析这些研究，在 Agent 力量下会加速。不是因为我们更会写数学，而是我们可以更快地自动化大量对照实验。

Matt Fredrikson

我理解你们对 codeex 与 Cloud Code 的重点场景。当前对代码类工具来说 Signal 已经有效，但要覆盖 openclaw 的全部工具行为，仍需要更多训练和迭代。

所以短期内仍是 trade-off：安全不能无限提高，但可以把可用性和安全性之间的曲线整体向上推。

Swyx

你们怎么看这种权衡在未来一两年的方向？

Zico Kolter

我们希望把可安全使用的点推得更靠右上：既保留大模型应用能力，也能通过分层防线控制误用。这个可行曲线比现在还更早出现。

Matt Fredrikson

计算机视觉仍是经典对抗场景，历史上是最早的脆弱面之一。只要没有足够信任，人类不会让其触达关键数据，系统就难以走到下一个生产阶段。

企业化部署、身份与监管议题

Matt Fredrikson

现在很多企业更关心的是：我不能只在家里用这些模型，怎么放进公司。通常他们先把 openclaw 试着接进内部流程，结果马上要考虑谁有权限、发起了什么动作。

如果只靠给 agent 套上默认权限，现实里仍可能越权，因为它执行链条复杂。真正的难题之一是 agent identity（身份模型）——权限应如何在系统内定义和传播。

Zico Kolter

当前很多组织默认让 agent 继承人类账号权限，这确实很不理想。我们也希望在同一组织内看到更细粒度、按任务的身份模型，而非无限放大单一账号。

更现实的是可用性：每项任务都要授权一次太痛苦，长期会退化成总是授权。我们需要既不放弃安全，也不让人类工作流崩掉。

Matt Fredrikson

所以我预期先是“多身份/多人格”的模式，比如工作与个人分离，而不是每个应用一套账号。人类会分角色生活，agent 也应逐步拥有类似分身。

Swyx

展望 2026，Grey Swan 的重点是什么？

Zico Kolter

从实验室走向企业是核心。未来安全治理不会只属于 frontier labs，所有部署 AI 应用的企业都会关注同样问题，所以我们要把能力从大公司扩散到普通公司。

我最期待的是：研发者在把 agent 推向组织前，就能把安全要求内建进去。我们已看到很多团队意识到这点，这对市场是个明显信号。

Swyx

Arena 能否服务企业级私有化测试？

Zico Kolter

可以，我们提供 private arena 给企业，把真实部署场景匿名化后放进竞争平台。很多从安全背景转来的人先是来观察，再成为付费客户。

Matt Fredrikson

这类场景的难点是激励设计：既要避免奖励黑客行为刷分，又要避免参赛者只拿“可赚分”小技巧。我们用自动评分和人工复核组合，兼顾效率和有效性。

Zico Kolter

下一层是保险和合规。像 AUC2（AI Underwriting）这类机制，为高风险应用提供风险评估框架和减损建议非常关键，但行业标准仍在迭代。

Matt Fredrikson

严格说这还不是完整法规模板，但至少把技术性风险、检测响应、第三方验证的要素放在一起。更有潜力的是把 Shade 与 Signal 的评估链路直接接入保险决策。

Zico Kolter

灰天鹅（grey swan）这个名字符合现在阶段：最坏事件不一定突然到来，但我们已经能看见它可能发生。行业要做的是早点把防线搭起来，而不是等事故爆发后才补。

Swyx

谢谢两位，本期就是一场从研究到产品、从工具到治理的全景讨论。

Zico Kolter

谢谢邀请。我们也会持续推进这套安全研究和产品化。

Matt Fredrikson

谢谢大家，后续继续关注。
